## 1. 目的と対象

Windows向けのOSSデスクトップアプリとして、自分でスキャンした大規模点群を無償で後処理できる実用的なツールを作る。

CloudCompareでは扱いづらい規模の点群を対象に、実務でよく使う機能に絞る。読み込み、インデックス構築、表示、編集、処理、書き出しを通してout-of-coreで動作させる。

主な機能:

- LAS/LAZ、E57の取り込み。
- 点群の可視化とスキャン単位の表示切り替え。
- 手動位置合わせとICPによる剛体位置合わせ。
- 範囲選択、手動ノイズ除去、切り出し。
- ノイズフィルターと間引き。
- LAS/LAZ、E57への書き出し。
- プロジェクト保存、リビジョン切り替え、フォーク、履歴集約。

将来は、E57の画像を外部で色調整し、再取り込みして対応スキャンを再着色する機能を追加する。そのための画像・姿勢・対応情報は初期版から保持する。

## 2. 技術スタック

| 担当 | 採用方針 |
| --- | --- |
| アプリと処理コア | Rust |
| UI | egui + eframeを初期構成とする |
| 点群描画 | wgpu + WGSLによる専用レンダラー |
| LAS/LAZ入出力 | Rustの`las`クレートとLAZ対応機能を使用する方針 |
| E57入出力 | Rustの`e57`クレートを使用し、実ファイルで互換性を検証する |
| 内部ストレージ | 原解像度の空間チャンク（処理用）と、別管理の足し算型の表示用8分木 |
| 内部圧縮 | チャンク／ノード単位のbyte shuffle + Zstdによる可逆圧縮 |
| メタデータ | `serde` + JSONを初期構成とする |
| 並列処理 | 上限付きワーカープールをRust標準ライブラリで実装する |

座標・姿勢・描画行列の計算には`glam`を使用する。ICPなどの実装で必要になる場合、`nalgebra`や`rayon`等の追加採用を検討する。

UIと処理コアは分離する。点群の3D描画はwgpuで実装し、eguiは操作パネルや進捗表示を担当する。

位置合わせの既存実装を利用する場合、Open3Dなどを間引き点群だけ受け取る独立プロセスとして使用する案がある。採用は未確定であり、アプリ側が処理対象の規模とメモリ使用を管理する。

## 3. スキャンと位置合わせの単位

アプリ内の「スキャン」は、独立して剛体変換できる点群データセットを意味する。

| 入力 | スキャンの単位 |
| --- | --- |
| E57 | `data3D`の各要素を独立したスキャンとして扱う |
| LAS/LAZ | 1ファイルを1スキャンとして扱う |

LAS/LAZに複数の計測を結合したデータが入っていても、初期版ではファイル全体を一つの変換単位とする。

各スキャンは次を持つ。

- アプリ内のデータセットIDと元ファイルの識別情報。
- 元のGUID、名前など、対応する入力メタデータ。
- ローカル座標の原解像度点群。
- スキャン固有の処理用チャンクと表示用8分木。
- 元のスキャンposeと、リビジョンごとの追加の位置合わせ変換。
- 対応画像への参照。

位置合わせは回転・平行移動で行う。原解像度の点を移動して書き直す代わりに、変換を保存する。

スキャンはフォルダーのツリーにまとめられる。フォルダーにも追加変換を持たせ、中のスキャンと画像すべてに適用する（例: 階ごとにスキャンをまとめて位置合わせし、最後に建物全体を合わせる）。スキャンの変換は上位フォルダーから順に合成する。スキャンやフォルダーを別のフォルダーへ移す・フォルダーを解除するときは、点の位置が変わらないよう移動対象の変換を補正する。E57は1スキャンでも取り込み時にファイル名のフォルダーにまとめる（スキャナーはファイルごとに同じスキャン名を付けることが多いため）。フォルダー構成と変換はリビジョンごとの状態に含める。

スキャンごとのフィルターはローカル座標で処理できる。統合間引きやスキャンをまたぐ近傍探索は、位置合わせ後の共通座標で判定する。

## 4. 座標と単位

- 元点の座標精度を維持できる表現で保存する。
- CPUでの座標変換・位置合わせは倍精度を基本とする。
- GPUには近傍原点からの相対座標を単精度で渡す。
- 入力の座標系情報を保持する。初期版では座標系の再投影を対象にしない。
- 単位が不明な場合は取り込み時に指定する。メートル指定の選択・処理パラメーターと整合させる。

E57の点を取り込む際は、readerによるposeの自動適用を制御し、ローカル座標とposeを別に保存する。読み込み・表示・書き出しで二重に変換しない。

## 5. 取り込みと内部形式

取り込み処理はPotreeConverter 2.xの空間分割、八分木構築、LOD生成の考え方を参考にする。

```text
LAS / LAZ / E57
      ↓ バッチ読み込み、E57のスキャン分離
空間チャンクへの振り分け
      ↓ 大きすぎるチャンクを再分割
原解像度の点データ + 空間インデックス
      ↓ チャンクの下も分割し、子の点から格子で選んで親へ上げる
表示用8分木（足し算型）
```

インデックス構築自体もout-of-coreで行う。全点をRAMに保持する工程を作らない。

原解像度の空間チャンクと表示用8分木は分けて保存する。原解像度のチャンクは取り込み完了後に点順序を固定し、編集によって書き換えない。

チャンクは論理的に分け、物理的には大きなデータファイルにまとめてオフセットとサイズで参照する。永続資産を大量の小さなファイルへ分散させない。取り込み途中の空間分割には一時ファイルを使用できる。

原解像度チャンクと表示用8分木のノードを独立したZstdブロックで可逆圧縮し、必要なブロックだけを展開する。圧縮して容量が増えるブロックは無圧縮で保持する。圧縮・再圧縮によって点順序や点参照を変更しない。現在はスキャン単位の点ファイルとLODファイルを使用し、安定版の形式・ファイル分割・互換性方針は今後確定する。

点群は役割の違う2つの構造で持つ。

| 構造 | 中身 | 分割 | 用途 |
| --- | --- | --- | --- |
| 処理用チャンク | 原解像度の全属性レコード | 8分木の葉。点数の上限（既定65,536点）で分割を止める | 範囲選択、フィルター、位置合わせ、書き出し、点のレイヤー |
| 表示用8分木 | 座標・色・元の点への参照だけの軽い点 | 処理用の8分木の下を、さらに葉が十分小さくなるまで分割する | 画面表示と、表示点を使う操作（ピック、選択プレビュー） |

表示用8分木はPotree 2と同じ足し算型とする。全点が表示用8分木のどれか1つのノードにちょうど1回だけ入り、ノードの点は、そのノードの箱を一辺128分割した格子で、子が持つ点からセルごとに中心に最も近い1点を選んで子から取り上げたものになる。親と子を同時に描いても二重にならず、上位から順に足していくだけで密度が上がる（面の点群なら1階層あたり約4倍）。処理用チャンクの点数上限で表示の階層が止まらないため、葉で密度が急に上がることもない。表示用の点は元の点への参照を持つので、点のレイヤーは表示側でもそのまま判定する。

2つの構造は点の参照（データセットID・チャンク番号・チャンク内の番号）でつながる。編集は常に処理用チャンクに対して行い、表示用8分木は書き換えない。表示用8分木は見るための写しであり、作り方を変えるときは作り直せる。全点の座標・色・参照を重ねて持つ分、ディスク使用量は増える。

取り込みでは、処理用チャンクごとにその中の表示用の部分木をワーカーで作り、チャンクの根の点を一時ファイルへ書き出す。全チャンクの後、処理用の8分木を下から上へたどり、各ノードで子の根の点から格子で選んで取り上げる。一度にRAMに置くのは1ノードの子の点だけとする。

取り込みの並列化は独立した点バッチ・チャンクを処理単位とし、計算と書き込みを分離する。処理中と書き込み待ちの結果に容量を予約し、CPU数だけでなくメモリ予算と同時タスク数を制限する。並列タスクの完了順によって確定後の点順序や点参照が変わらない構成とする。スキャンが予算に収まればRAM上で分割し、収まらなければ格子での計数と1回の振り分けで一時ファイルI/Oを抑える。

表示用8分木の生成は、ユーザーが実行する間引きと区別する。表示用8分木を生成しても原解像度の点数は減らない。

COPCは将来の入出力候補であり、初期版の編集用内部形式は独自形式とする。

### 計算用座標の持ち方

以前の点レコードは、先頭に計算用のXYZをf64で持ち、その後ろに元の属性（E57の型のままの座標、LASの整数座標など）も保持していた。座標を重ねて持つうえ、スケールで量子化された値をf64にすると下位ビットがばらつき、圧縮が効きにくい。実データのLASでは、同じ座標がf64で1点18.9 byte、LASの整数のままで4.8 byte（Zstd level 3、圧縮後）だった。

そのため、元の値を失わずに次の形で持つ（2026-10-07に実装。詳細は[internal-format.md](internal-format.md)）。

- 直交座標を持つスキャンは計算用XYZを保存せず、読み出すたびに元の属性から求める。単精度は倍精度に広げ、倍精度はそのまま使い、スケール付き整数は整数×スケール＋オフセットで求める。どれも誤差なく毎回同じ値になる。
- LASから取り込んだスキャンは、E57用の座標属性をLASと同じscale・offsetのスケール付き整数とし、LASの整数をそのまま持つ。座標はスケール付き整数の規則で求め、E57へも整数のまま書き出す。
- 球面座標だけを持つE57は、読み出しのたびに三角関数を計算しないよう、計算用XYZをf64で保存する。直交座標と球面座標の両方を持つ場合は直交座標だけを使う。
- 座標を求める計算は1つの関数にまとめ、取り込み・読み出し・書き出しで同じ式と順序を使う。結果のbit列は常に同じになり、表示点による選択プレビューと原解像度点による確定結果の一致を保つ。
- 描画用RGBAと座標の有効フラグは先頭部に持つ。
- 表示用8分木の点も、座標を元の点と同じ表現（スケール付き整数、単精度、倍精度、球面座標のみのスキャンではf64）で持ち、同じ関数で求める。Potree 2も整数×スケール＋オフセットで持つが、独自のスケールで量子化し直すと、表示点を使う選択プレビュー・ピックと計測・ICPのサンプルが原解像度点と最大でスケールの半分ずれる。元の表現のままならずれない。
- 保存形式の変更なので、以前のプロジェクトは開かず、取り込み直す（公開までは形式バージョン1のまま変更する方針による）。

取り込み直して計測した容量（Zstd level 3）:

| データ | 座標の元の型 | `.points` | `.view` | 合計 |
| --- | --- | ---: | ---: | ---: |
| 自宅屋内のLAS（2,662万点、点形式7） | LASの整数 | −46% | −64% | 1,554 → 738 MiB（−53%） |
| manitouNoInvalidPoints.e57（110万点） | スケール付き整数 | −70% | −57% | 48.5 → 17.1 MiB（−65%） |
| Trimble_StSulpice-Cloud-50mm.e57（848万点） | 単精度 | −40% | −2% | 271 → 201 MiB（−26%） |

自宅屋内のLASでは、プロジェクトの点と表示用8分木の合計が元のLAS（1,162 MiB）の約1.3倍から約0.63倍になった。単精度の座標をf64に広げた値は下位ビットが0のため、以前から表示用8分木では圧縮が効いており、Trimbleの`.view`はほとんど変わらない。

## 6. 点の識別

安定した点参照を設ける。全ての元点へ独立したID属性を追加することは必須としない。

```text
PointRef = データセットID + 原解像度チャンクID + チャンク内の点番号
```

- チャンク内の点番号は固定した配列位置から求める。
- 表示用8分木の点には、対応する元点への参照を保存する。
- 削除、復元、選択、近傍処理で同じ参照を利用する。
- 取り込み中の並べ替えは許可し、チャンクと点順序の確定後に参照を成立させる。
- 再取り込みで同一IDになることは保証しない。
- 元ファイル内の点番号との対応を保存するかは未確定。

参照はファイル内のバイト位置や一時的なGPUバッファ位置に依存させない。

新しい点を生成する処理や統合結果は、別の派生データセットとして扱う。派生点から元点への由来情報をどこまで保持するかは別途決める。

## 7. レイヤー

すべての元点は、ちょうど一つのレイヤーに属する。取り込んだ点は既定のレイヤー「点群」に入る。範囲選択・3Dボックス選択・ノイズ除去・SOR・間引きは点を消さず、判定した点を別のレイヤーへ移す。戻すときは、移した先のレイヤーから点を選んで元のレイヤーへ移す。レイヤーは「どこで計測した点か」を表すスキャンのツリーとは独立した軸で、CADの画層と同じ考え方とする。

| 操作 | 既定の移動先 |
| --- | --- |
| 範囲選択、3Dボックス選択 | 削除 |
| ノイズ除去、SOR | ノイズ |
| 間引き | 間引き |

移動先のレイヤーは、なければ操作と同時に作る。操作ごとに移動先を選べ、既存のレイヤーやユーザーが作ったレイヤーにも移せる。

- レイヤーには名前と表示・非表示がある。作業の対象は表示中のレイヤーの点とする。表示、選択、フィルター、位置合わせ、書き出しは、表示中のレイヤーの点だけを扱う。非表示のレイヤーの点は処理されない。
- 既定のレイヤー「点群」は削除・改名できない。他のレイヤーを削除すると、その点は「点群」へ戻る。
- レイヤーの全点を別のレイヤーへまとめて移せる。ノイズ除去の条件を変えてやり直すときは、ノイズの点を「点群」へ戻してから実行する。
- 一つの点が複数のレイヤーに属することはない。戻した点は、どの操作で移されていても確実に表示へ戻る。

内部では元点の座標・属性を複製せず、点ごとの所属レイヤー番号（u8、0が「点群」）をチャンク単位のラベル配列として持つ。全点が「点群」のチャンクには配列を持たない。ラベル配列は一度書いたら変更しない。点を移す操作は、点の所属が変わったチャンクだけの新しいラベル配列をまとめた「ラベルパッチ」を書く。作業状態はレイヤーの定義（番号・名前・表示）と、適用するパッチの順序付きの一覧を持ち、各チャンクは一覧で最後に現れるパッチの配列を使う。

元に戻す・やり直す・リビジョンの切り替えは、作業状態の差し替えだけで行う。点データもラベル配列も書き換えず、再計算もしない。どのリビジョンや作業状態からも使われなくなったパッチは、クリーンアップで削除する。

点の移動で点配列を詰めない。通常の削除では原解像度データのディスク容量は減らない。

近傍数を使うフィルターなどは、実行時に表示中だった点の集合に依存する。点を戻しても、後の操作の結果は自動では再計算しない。

編集結果は表示にも反映する。表示用8分木の点は元の点の参照で所属レイヤーを判定する。上位のノードの点が非表示のレイヤーに移って表示が不十分になる場合は、表示の予算を表示中の点数で数え、深い階層まで描いて補う。

再着色（将来）は所属レイヤーとは別に、チャンクごとの新しい色として重ねる。

## 8. 選択と奥行き制限

画面上の矩形・多角形選択と、XYZ軸まわりに箱を回せる3Dボックス選択を実装した。箱の外も表示したまま内部の点を黄色で強調するハイライト（シェーダーで箱の内外を判定）と、箱の内外の点のレイヤー移動に使う。

カメラはターゲットを中心としたオービット操作とする。左ドラッグで回転、右ドラッグでパン、ホイールでズームする。範囲選択モードでは左操作を選択へ割り当てる。

多角形選択には奥行き設定を設ける。

- 表示対象スキャンの、表示中のレイヤーに属する有効な原解像度点のうち、選択範囲内の最も手前の点を基準とする。複数スキャンでも共通の基準を用いる。
- 基準からカメラの前方方向へ、指定したメートル数までの点を選択する。
- 奥行き設定を維持し、カメラ移動と選択・除去を繰り返せるようにする。
- 最も手前の点が外れ値であれば、範囲選択と除去を繰り返して対処できる動作とする。
- カメラ姿勢、多角形、奥行き条件は各操作の実行時点で記録する。その後のカメラ移動で実行中の判定条件を変えない。

範囲判定と基準点の確定は原解像度の点を対象とする。画面に描かれた表示用の点だけを移す動作にはしない。必要に応じて表示用データでプレビューし、確定結果と区別する。

移す側は2種類とし、用途を分ける。移した点は選んだレイヤー（既定は「削除」）へ入る。

| 操作 | 対象 | 用途 |
| --- | --- | --- |
| 範囲内（奥行き制限あり） | 選択範囲内で、最も手前の点から奥行きの厚さまで | 点群内を移動しながら目の前のノイズを消す |
| 範囲内（奥行き制限なし） | 選択範囲を通して見える点すべて（無限遠まで、カメラ後方は除く） | CloudCompareの分割と同様の除去 |
| 範囲外 | 選択範囲を通して見えない点すべて（奥行きは使わない） | 上面・側面から境界を囲む切り出し |

奥行き制限は範囲内のオプションとする。制限なしの範囲内と範囲外は、同じ選択に対して互いに補集合となる。奥行き付きの範囲外（奥行き範囲の補集合）は扱わない。薄い層の抽出は3Dボックス選択で指定する。

プレビューでは移動予定の表示点を強調する。表示点は原解像度点の一部のため、範囲内でも原解像度から求めた基準点を使えば、表示点についての判定は確定結果と一致する。基準点はバックグラウンドで求め、それまでは表示点だけから求めた近似値で仮表示する。奥行きを制限しない場合は基準点を使わず、プレビューは最初から確定結果と一致する。表示されていない点の結果はプレビューに現れない。

### クリッピングボックス（今後）

建物内部など、注目する範囲だけを表示する箱を設ける。点のレイヤーは変えず、表示上で見えなくするだけとする。

- 箱の外の点は描画しない。表示用8分木のノード選択でも箱の外のノードを除き、描画点数を箱の中に集めて細部まで表示する。
- 箱の外の点は操作の対象にしない。範囲選択・3Dボックス選択は原解像度の判定でも箱の中の点に限り、ピックと計測は描かれた点だけを使う。
- フィルター・位置合わせ・書き出しは箱の影響を受けない。箱があることを画面上で示す。
- 箱の操作は3Dボックス選択と同じ取っ手を使う。

## 9. リビジョンとフォーク

リビジョンを木構造で保存する。任意のリビジョンへの切り替えと、その時点からのフォークを可能にする。

```text
取り込み
  └─ 手動位置合わせ
       └─ ICP
            ├─ ノイズ除去: 弱め
            │    └─ 手動削除
            │         └─ 間引き: 5 mm
            └─ ノイズ除去: 強め
                 └─ 間引き: 10 mm
```

各リビジョンは、親、操作とパラメーター、対象と入力状態、変換行列、レイヤー構成、確定済み結果への参照、名前・日時・メモを持つ。状態を復元できるメタデータを保存し、切り替えだけでフィルターを再計算する必要がない構成とする。

元点群、画像、既存の処理結果は枝の間で共有する。分岐時に点群全体を複製しない。過去の状態から新しい操作を実行しても、既存の後続履歴は別の枝として残す。

パラメーター調整中はプレビューとして扱う。操作が正常に完了すると未保存の作業状態に反映し、ユーザーが明示的に保存した時点でリビジョンを確定する。個々の編集（レイヤーの表示切り替えなど）ごとにリビジョンを増やさない。作業状態は編集のたびにディスクへ書き込み、異常終了しても失わない。編集単位の取り消しは作業状態の元に戻す・やり直すで行い、ユーザーに履歴として見せない。

UIにはスキャンのツリー・レイヤー一覧と、現在のリビジョン表示を常に出す。リビジョンのツリーはプロジェクトを開いたとき（リビジョンが複数あるか未保存の作業があるとき）と、メニューから開く一覧で示す。基本操作は「保存（Ctrl+S）」「開く（切り替え）」「名前を付ける」「削除」「この状態を書き出す」とする。過去のリビジョンを開いて編集・保存すると枝になる。

## 10. 履歴の集約とクリーンアップ

選んだ時点の状態を新しい基準状態として保存し、そこまでの細かい履歴を集約できるようにする。

| 操作 | 動作 |
| --- | --- |
| 履歴を集約 | 過去の操作履歴をまとめ、現在の各点の所属レイヤーは残す |
| ラベルも統合 | 積み重なったラベルパッチを、チャンクごとに一つの配列へまとめる。所属レイヤーは変わらない |

元点群は共有し、点参照を維持する。

集約する枝を選べるようにし、他の枝が使う履歴・処理結果は保持する。どの保持対象からも参照されないデータをクリーンアップする。履歴の短縮とディスク容量の削減は区別する。

実行前に対象範囲、残す枝、戻れなくなる履歴を表示する。新しい基準状態の保存成功後に、不要なデータを整理する。

残存点だけで原解像度チャンクを再構築する物理的な最適化は、点参照を変える操作であり、通常の履歴集約から分離する。初期の検証対象には含めない。

## 11. E57の画像と構造の保持

スキャンと画像は1対多で管理する。画像は独立した資産とし、左右カメラや複数時点の画像を保持できるようにする。

```text
スキャン
├─ 点群 + スキャンpose
├─ 画像A: 画像pose + 投影情報
└─ 画像B: 画像pose + 投影情報
```

保持対象:

- スキャンと画像それぞれのGUID、pose、名前などのメタデータ。
- 画像とスキャンの関連付け。
- 元の画像データ、投影方式、画像サイズ、投影パラメーター、有効画素マスク。
- 存在する場合は画像の撮影時刻、点の行・列番号、点・色の有効性情報。

E57の数値属性は元の型と値を保持する。scaled integerは元の整数とscale/offset、球面座標は元の球面属性を残し、表示・計算用のXYZは別に持つ。無効点も元のレコードを保持して表示から除外する。表示用の色変換で、元のRGB属性を書き換えない。

スキャンposeと画像poseを別々に保存する。位置合わせでは同じ追加変換を対応スキャンと画像に適用し、相対関係を維持する。

スキャンと画像の対応が入力に存在しない場合は、その欠落を記録する。推定で確定した対応として保存しない。対応の補完方法は別途決める。

E57書き出しでは、残った点の行・列番号を元の値のまま保持する。削除・間引きに合わせて点数、範囲などのメタデータを整合させ、画像の関連付けとposeを維持する。他のソフトで再読込し、画像との対応まで検証する。

点群の行・列番号は写真の画素番号と同一とは限らない。将来の再着色では画像poseと投影情報による対応付けを基本にする。

### 単独のパノラマ写真

全天球カメラ（Insta360等）で別に撮影した正距円筒図法の写真を、プロジェクトに配置できるようにする。

- 画像ファイルを取り込み、スキャンに属さない画像として保持する。E57へは球面画像（SphericalRepresentation）として姿勢付きで書き出す。
- 写真はツリー上でスキャンと別種の項目とし、フォルダーに入れられる。スキャン・フォルダーと同じく自身の追加変換を持ち、リビジョンで管理する。
- 撮影位置は未知とし、位置と向きを同時に求める。写真上のクリックは撮影位置からの方向、点群上のクリックは3次元の点として対応付け、方向の角度誤差を最小にする。誤対応を見つけられるよう4組以上を必須とし、組ごとの誤差を表示する。

位置合わせの画面は左右に分割し、左を点群ビューアー、右をパノラマビューアーとする。半透明の画像と点群の重ね合わせで合わせる方式は操作が難しいため採らず、重ね合わせは結果の確認に使う。

- パノラマビューアーは球の中心からの透視表示を基本とし、ドラッグで向き、ホイールで画角を変える。拡大して細かい対象を指せるようにする。探索用に正距円筒の全景表示へ切り替えられる。
- 画像はGPUのテクスチャ上限（一般に8192px）を超える大きさ（Insta360で約12K×6K）を想定し、タイルに分けて読み込む。
- 対応点は既存の対応点ツールと同じく、どちらの画面のクリックも空きのある最初の組へ入れ、番号付きのマーカーを両画面に表示する。写真側は元画像の画素座標、点群側はスキャンとスキャン座標で保持する。方向は画素座標と投影から都度求める。
- 対応点の組は写真に属するデータとしてプロジェクトに保存し、後から組を追加して解き直せるようにする。
- 初期値は方位を全周で探索して求める（P3Pは使わない）。0.5°刻みの各方位で、写真の方向から伸ばした光線群に最も近い点を撮影位置とし、全組の角度誤差が最小のものを選ぶ。その後、角度誤差の二乗和をLevenberg–Marquardt法で最小化する。水平を外すときは、水平での結果から傾きを含めて詰める。
- 水平の仮定（既定でオン）では、写真が水平補正済みで点群のZが鉛直という前提で、位置と方位の4自由度だけを求める。オフでは6自由度を求める。
- 結果は組ごとの角度誤差（度）と画素ずれで示し、写真上にクリック位置と点の投影位置を結ぶ線を表示する。既存の位置合わせと同じく、プレビューを確認してから適用する。
- 解が得られたら、点群側のカメラを推定した撮影位置に置き、パノラマビューアーの向きと画角に合わせる連動表示を使える。確認用に点をパノラマ上へ投影して重ねる。

配置した写真は、点群上の撮影位置にマーカー（表示を切り替えられる）で示し、クリックで中央の画面をその写真の表示にする。表示中は向きと画角だけを変え、撮影位置からは動かない。写真に写る他の写真のマーカーから、向きを保ったまま移れる。

写真の座標系はE57の球面画像の規約（画像中心が+X、方位角は左へ増える）に合わせ、書き出し時に変換しない。GPUのテクスチャにミップマップがないため、全解像度の他に半分ずつ縮小した版を持ち、表示倍率で選ぶ。

書き出したE57を取り込み直したときに、スキャンに属さない球面画像をパノラマの項目にする処理は未実装。

## 12. 将来の画像編集と再着色

次のワークフローを目指す。

1. 対応する球面画像を画像ファイルと対応情報のJSONとして取り出す。
2. 外部ソフトで明るさ・色味を調整する。
3. 同じ画像サイズ・投影を維持した画像を再取り込みする。
4. 対応スキャンの点を画像へ投影し、チャンク単位で再着色する。
5. 新しい色レイヤーとリビジョンとして結果を保存する。

元画像と元のRGBは変更しない。調整画像は元画像から派生した版として管理し、確定済みリビジョンは使用した版と着色結果を保持する。

最初はリサイズ・切り抜き・回転を伴わない色調整と、単一画像からの再着色に絞る。E57には球面以外の投影画像も存在するため、元の投影情報を保持し、球面画像の取り出しから対応する。

「スキャンに属する画像」と「各点の着色に使う画像」を区別する。複数画像による着色では画角・距離・遮蔽などを考慮する必要があり、選択・合成方法は将来決める。

## 13. フィルターと位置合わせの初期範囲

- ノイズ除去は半径と近傍点数による孤立点除去から開始する（実装済み）。
- ノイズ除去と間引きは、判定した点を別のレイヤーへ移す。原解像度の点は書き換えない。スキャンごとにスキャンの座標で、チャンクとその範囲に掛かる隣接チャンクを読んで判定する。
- SOR（統計的外れ値除去）も実装した。k近傍の平均距離をkd木で求め、スキャンごとの平均と標準偏差を1回目で集計し、2回目で判定する。近傍の読み込み範囲は探索範囲で制限し、その中にk点ない点は外れ値とする。
- 間引きは、ボクセルごとに元点を一つ選ぶ方式を基本とする。元点の属性を維持する。ボクセル中心に最も近い点を選び、同じ距離ならチャンク番号・点番号の小さい点を選ぶ（実装済み）。
- 位置合わせは、2点群間の対応点による初期位置合わせとICPを初期範囲とする（実装済み）。対応点はHornの四元数法、ICPは点と面の距離を最小にし、Huber重みで外れた対応を抑える。対応距離は収束するたびに半分にし、基準の点間隔の3倍まで縮める。動かす対象はスキャンかフォルダーで、結果は上位フォルダーの変換を考慮した自身の追加変換として保存する。
- ICPには処理用に間引いた点群を使用する。表示用8分木を根から階層ごとに、点数の予算に達するまで集める。基準側は動かす側の範囲（最大対応距離を加えた箱）に限る。
- 複数スキャンの一括最適化は将来の拡張とする。

近傍処理は隣接チャンクを考慮し、チャンクごとに独立して処理したために境界で結果が変わる実装を避ける。

## 14. 統合、間引き、書き出し

通常の間引きはスキャンごとに実行する。複数スキャン全体を間引く場合は、位置合わせ済みの共通座標へ変換して統合し、共通のボクセルグリッドで処理する。チャンク・スキャン境界をまたぐ同一ボクセルも統合する（実装済み。間引いた点は各スキャンの点のまま別のレイヤーへ移し、統合点群の保存は未実装）。

次の操作を用意する。

- 統合点群を作成: 派生データセットとして保存し、確認や追加処理を可能にする。
- 統合・間引きして書き出し: 同じ処理を行い、結果を直接出力する。

元スキャンと画像はプロジェクトに残す。統合点群は各スキャンの変換が適用済みで、以後は全体を一つの変換単位として扱う。

LAS/LAZはスキャン別と結合出力に対応する。出力形式は保持する属性・WKTに合わせ、拡張属性またはWKTが必要ならLAS 1.4を使う。E57は複数スキャンと対応画像を保持する。統合点群を一つの点群としてE57へ出力する際の画像の関連付け・由来表現は別途決める。

書き出しでは原解像度チャンクを順次読み、選択したリビジョンのレイヤー構成、色、変換を適用する。非表示のレイヤーの点は出力しない。

## 15. LAS/LAZの属性

座標、色、強度を基本属性として扱い、座標系情報を保持する。

分類・リターン・分類フラグ・GPS時刻・NIR・Extra BytesなどをLAS属性レコードとして保持し、LAS/LAZへ書き戻す。VLR/EVLR、GPS時刻の種類、Extra Bytesの定義も保持する。旧版で省略した属性は取り込み直すまで復元できない。

波形パケットの関連データは未対応であり、波形付き入力を取り込み前に拒否する。LAS固有属性はE57へは書き出さず、書き出し画面で注意を表示する。内部レコードの詳細は[internal-format.md](internal-format.md)を参照する。

書き出し時は、実際に保持する属性に合わせて点形式と属性定義を整合させる。結合対象に不一致があれば書き出し画面に除外対象を表示し、「すべて保持」「不一致の属性・付加情報を除いてまとめる」「スキャン別出力」を選べる。VLR/EVLRの説明文・並び順の違いは不一致に含めず、user ID・record ID・データで比較する。除外モードではExtra Bytesの長さ・定義が違うと拡張属性全体と定義を除き、GPS時刻の方式が違うと時刻を除く（拡張点形式などの必須フィールドは0）。座標系が違うと座標系情報を除き、座標は自動変換しない。共通のVLR/EVLRと互換性のある点属性は保持する。元のプロジェクトを変更せず、座標変換を反映し、点数・範囲・座標のscale/offset・LAZ圧縮メタデータは再生成する。

## 16. プロジェクト、ジョブ、リソース

プロジェクト内に取り込み済み点データ、画像、編集結果、履歴を保存する。元ファイルを移動しても保存済みの作業を再開できる構成とする。

プロジェクトを開いている間はOSの排他ロックを保持し、他プロセスからの起動を拒否する。UIとワーカーの参照はロックを共有し、最後の参照の解放またはプロセス終了時にロックが解放される。旧版との同時編集には対応しない。

利用可能なRAM・VRAMを十分に使う自動調整を基本とする。安全弁として利用上限を設定できるようにし、固定された小さな上限を前提にしない。

out-of-coreの構造は維持する。チャンク、処理中バッファ、RAM・VRAMキャッシュ、同時ジョブ数を管理し、近傍処理で隣接データを無制限に一括読込しない。表示は視野と画面上の大きさに応じたLODを選び、必要なデータを段階的に転送する。

表示はPotreeと同じ方式とする。視錐台と画面上の大きさから優先度を付けて表示用8分木のノードを選び、点数の予算に達するまで上位から足していく。選んだノードはファイルのバイト範囲を読み、展開してGPUに常駐させ、カメラを動かしても読み直さない。新しく必要になったノードだけを読み込み、使われなくなったノードは予算の2倍を上限とするLRUで捨てる。

表示用RGBはsRGBとして扱い、シェーダーと描画先・UIへのテクスチャ受け渡しの色空間を整合させる。読み込んだノードはGPUに常駐させ、カメラ移動中も点を減らさず、新しく見えたノードだけを優先度順に読んで少しずつ足す。展開済みノードを再利用し、カメラ移動だけでデータを繰り返し読み直さない。展開済みノードはスキャンのローカル座標で保持し、スキャンごとの変換はGPUで描画時に掛ける。位置合わせの入力中は適用前の変換で表示し（ライブプレビュー）、適用しても読み直さない。

長時間ジョブには進捗とキャンセルを設ける。取り込みは完了済みの処理単位を保存し、再開可能な構成にする。

処理中の結果は一時的な作業領域に保存し、正常完了後にリビジョンとして確定する。キャンセルや異常終了によって、直前の確定済み状態を破損しない。未完了ジョブの再開単位や保存方式は別途設計する。

各ジョブの入力リビジョンを固定し、作業中のリビジョン切り替えによって処理条件や結果の所属先を変えない。

作業用・一時データも含めたディスク容量を見積もり、長時間処理の開始時に空き容量を確認する。

## 17. 最初の検証目標

複数スキャン・複数画像を含む実際のE57を使い、次を一通り成立させる。

1. スキャンを分離して取り込み、画像と対応情報を保持する。
2. out-of-coreで表示する。
3. 奥行き付き範囲選択で点を削除レイヤーへ移す。
4. プロジェクトを保存し、再開して同じ状態を復元する。
5. スキャン構造・pose・画像との対応を保持してE57へ書き出す。
6. 他のソフトで再読込し、点数、座標、属性、画像対応を確認する。

計測対象はピークRAM・VRAM、作業ディスク容量、取り込み時間、再オープン時間、選択の応答時間、書き出し時間とする。

その後、リビジョンの切り替え・フォーク・集約、LAS/LAZ入出力、位置合わせ、フィルター、間引きを順次検証する。

現在はmanitouNoInvalidPoints.e57（5スキャン・約110万点・5画像）とTrimble_StSulpice-Cloud-50mm.e57（5スキャン・約848万点・RGBあり・画像なし）で、取り込みとE57への書き戻しを照合した。小さな生成データでは複数画像・独立したpose・レイヤー移動・分岐も検証している。検証方法・性能実測は[開発・検証](development.md)を参照する。他ソフトによる画像対応の再確認、億点以上の規模とピークRAM/VRAM・一時ディスク使用量の評価は今後の検証対象とする。

## 18. 未確定事項

- 普段の点数、最大点数、スキャン数、画像数。
- 対象PCのRAM、GPU・VRAM、SSD容量と性能。
- 主に使うスキャナーと、追加の互換性確認用データ（億点以上、SLAM、複数カメラ等）。
- チャンク・圧縮ブロック容量の最適値、ファイル分割、安定版形式と互換性・移行方針、大量のノードを持つ場合のメタデータ管理。
- E57の圧縮データ読み出しの並列化、VRAM予算の自動調整、GPU転送の予算と常駐管理。
- フィルターの既定値、ICPの詳細方式と品質評価、ボクセル代表点の選択方法。
- 画像対応・投影情報が欠落している場合の補完方法。
- LASのその他の標準属性と、派生点の由来情報の保持範囲。
- 再着色レイヤーが複数ある場合の適用規則と、複数画像の選択・合成。
- 再開可能なジョブの詳細と、未完了データの整理方針。
- 指定エリアごとの書き出し（保留）。エリアは点のレイヤーではなく空間の範囲として定義し、書き出し時に判定すれば、取り込みや位置合わせの後も自動で反映される。点群を利用する側のアプリで範囲を判定する方法もあるため、必要になるまで実装しない。
