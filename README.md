# Geemil Workbench

Windows向けのOSS点群編集アプリ。Rust / egui / wgpuで、原解像度の点をディスクに保持し、Potreeと同じ足し算型の表示用8分木から、視点に応じたノードだけを読み込んでGPUに常駐させる。設計方針は[docs/design.md](docs/design.md)、現在の内部形式は[docs/internal-format.md](docs/internal-format.md)を参照。

現在は、取り込みから手動編集、E57への書き出しまでを試すための初期プロトタイプ。プロジェクト形式は暫定版で、将来の版との互換性は未確定。

## 起動

WindowsのRust MSVC環境とC++ Build Toolsが必要。Rustの版はリポジトリの`rust-toolchain.toml`で固定している（現在1.99.0、egui 0.36の要件は1.95以上）。rustupが自動で取得する。初回ビルドは依存ライブラリをダウンロードする。

```powershell
cargo run -p geemil-desktop --release
```

既存のプロジェクトフォルダーを指定して起動できる。

```powershell
cargo run -p geemil-desktop --release -- work-data/trimble
```

WindowsではDirectX 12を既定とする。`WGPU_BACKEND`環境変数でバックエンドを指定できる。画面の日本語フォントはWindowsのメイリオ／游ゴシックを使用し、配布物には同梱しない。

配布物は`cargo build -p geemil-desktop --release`で作る`target/release/geemil-desktop.exe`の1ファイルだけでよい。`.cargo/config.toml`でCランタイムを静的リンクしているため、Visual C++再頒布可能パッケージは不要で、Windows標準以外のDLLに依存しない。CLIが必要な場合は`geemil.exe`も添える。`target`のそれ以外の中身はビルド用の中間生成物で、配布しない。GUIアプリとしてビルドするため、起動してもコンソールウィンドウは開かない。スモークテストの出力は、リダイレクトしていればそこへ、ターミナルから直接実行した場合はそのターミナルへ出る。

## 操作

画面は上からメニューバー、アイコンのツールバー、選択中のツールのオプションバー、左にプロジェクトツリーとレイヤー、下にステータスバー。プロパティはツリーの右クリックからダイアログで開く。キー操作の一覧は「ヘルプ → キーボードショートカット」にある。

ツリーのスキャン・フォルダーをダブルクリックすると、現在の視線方向を保ちながら対象全体が画面に収まる位置へカメラが移動する。フォルダーでは配下のスキャン全体を対象にする。ビューアー右下のXYZヘルパーはカメラの向きに連動し、Xを赤、Yを緑、Zを青で表示する。

1. 起動画面か「ファイル → 新規プロジェクト」（Ctrl+N）で名前と保存先を指定する。作成すると空のプロジェクトが開き、画面中央の「点群を取り込む…」か「ファイル → 点群を取り込む…」でE57・LAS・LAZを追加する。点群ファイルをウィンドウにドロップしても始められる。プロジェクトがなければ作成画面を開き、作成後に取り込む。最近使ったプロジェクトは起動画面とファイルメニューから開ける。
2. 「点群を取り込む」（Ctrl+I）でE57、LAS、LAZを選択する。E57は`data3D`ごと、LAS/LAZはファイルごとに独立したスキャンとなる。複数スキャンを含むE57は、ファイル名のフォルダーにまとめる。
3. 「カメラ操作」（V）では左ドラッグで回転、右ドラッグで平行移動、ホイールでズームする。ダブルクリックした位置の表示点を回転中心にする。表示点をクリック（ホイールクリックも）すると、その点のスキャンをツリーで選択し、折りたたまれたフォルダーを開いてその行までスクロールする。ホイールドラッグでの回転とホイールダブルクリックでの回転中心の指定はどのツールでも使えるので、矩形選択などのままで視点を変えられる。点群の中を移動するには、どのツールでも矢印キー（↑↓で視線方向に前進・後退、←→で左右）とPageUp/PageDown（上下）を使う。回転中心も一緒に動き、1秒に回転中心までの距離だけ進む。Shiftで4倍速く、Ctrlで4分の1に遅くなる。Ctrl+ホイールでも回転中心ごと前進・後退するので、ホイールの拡大縮小と違い回転中心を通り抜けられる。全体表示（F）と上面・正面・側面・等角（7・1・3・5）は表示メニューにある。カメラが一度に動くため、押し間違えないようツールバーには置かない。平行投影（O）と陰影強調EDL（E）はツールバーと表示メニューにある。平行投影では奥行きによる大きさの変化がなく、ホイールで表示範囲を拡大縮小する。断面や平面図の確認、範囲選択にも使える（範囲選択は平行投影の視線で判定する）。描画点数（既定200万点、10万点単位）と点サイズはツールバーで変え、次回起動時も保持する。点サイズの横で「適応」を選ぶと、PotreeのADAPTIVEと同じく、各点をその場所で表示中の一番深いノードの点間隔（箱の最長辺の1/128）の1.7倍の大きさで描く。細かいノードが表示されていない場所、たとえば孤立した点やまばらな所ほど点が大きくなるので、Potreeで公開する前にノイズの見え方を確認できる。点サイズの2がPotreeのサイズ1に当たる。判定はスキャンごとの表示用8分木で行うため、全スキャンをまとめて変換したPotreeとは細部が異なる。点の色はツールバーか表示メニューで「RGB」「高さ」「スキャンごと」から選ぶ。「高さ」は表示中の点の高さの1〜99%の範囲をTurboの色で表し、色のないスキャンでも形が読みやすい。「スキャンごと」は位置合わせの確認に使える。どちらもシェーダーで色を付けるため、切り替えで読み直さない。
4. プロジェクトツリーはCtrlで追加・解除、Shiftで表示中の行の範囲選択、Ctrl+Shiftで範囲の追加ができる。選択した複数項目をまとめてドラッグして移動でき、右クリックの移動先・表示・非表示・これだけ表示・プロジェクトから外すも選択項目へ適用する。フォルダーとその子を同時に選んだ場合、移動は親だけを処理し、子も一緒に移す。プロジェクトツリーのチェックで表示を切り替える。フォルダーのチェックは中のスキャンをまとめて切り替える。右クリックで新しいフォルダー・名前の変更・移動先・フォルダーの解除・これだけ表示・プロジェクトから外す。ドラッグ＆ドロップでフォルダーへ移動できる。フォルダー名だけでなく、配下のスキャン行や余白もドロップ先になり、移動先の範囲を枠で示す。入れ子のフォルダーではカーソル位置の最も内側のフォルダーが移動先になる。移動や解除をしても点の位置は変わらない（変換を補正する）。
5. 左パネルはツリーとレイヤーの境界をドラッグして高さ配分を調整できる。スキャンやフォルダーを右クリックして「プロパティ」を開くと、点数・元ファイル・対応画像などをダイアログに表示する。「位置合わせ（追加変換）」でスキャンかフォルダーの平行移動量・XYZ回転角を入力すると、表示中の点がその場で動いてプレビューされる。「適用」で作業状態に反映し、「入力を戻す」で入力を取り消す。プロパティを閉じたときも未適用の入力を取り消す。フォルダーの変換は中のすべてのスキャンと対応画像に掛かるため、階ごとにまとめたスキャンを最後に建物全体として合わせられる。元の点は書き換えない。ツリーで選んだスキャンは向きに沿った白い箱で（点より奥にある辺は点に隠れる）、フォルダーはフォルダーの座標で中のスキャンを囲む箱で表示する（スキャンの箱は取り込み時の全点の範囲で、まばらな遠い点も含む）。「移動・回転」（T）ツールでは、選んだスキャンのスキャン位置（器械点）にPotreeのような取っ手を出す。スキャン位置を持たないもの（LAS/LAZ、姿勢のないE57）とフォルダーでは箱の中心に出す。E57の姿勢でも、全スキャンが同じ姿勢を共有するもの（位置合わせ済みの点群を共通のオフセットで書き出したファイルなど）や、原点が点の範囲から大きく離れるものはスキャン位置とみなさない。XYZの矢印をドラッグすると共通座標の軸に沿って平行移動し、XとYの矢印の間の青い四角をドラッグすると水平面（XY）内で自由に平行移動する（高さは変わらない。真横から見ているときは表示しない）。輪をドラッグするとその軸まわりに取っ手の位置を中心に回転する（水平を出したスキャンをZの輪で回すと、器械点を保ったまま向きだけを合わせられる）。表示中の点をダブルクリックすると、取っ手（回転の中心）をその点へ移す。動かすスキャン以外の点でもよく、すでに合っている建物の角などに置いてZの輪で回せば、その点を動かさずに向きだけを合わせられる。置いた取っ手は対象の座標で保持するため、移動や元に戻すに追従する。何もない所をダブルクリックするか、別の項目を選ぶかツールを切り替えると元の位置に戻る。ドラッグ中は移動量・角度を表示してプレビューし、離すと1回の編集として確定する（元に戻せる）。Escでドラッグを取り消す。
6. 「矩形選択」（R）では左ドラッグ、「多角形選択」（P）では左クリックで頂点を追加し、ダブルクリックかEnterで閉じる。Escで選択を解除する。選択は描いたときのカメラで判定するので、描き終えた選択は視点を変えても残り、移動予定の赤表示を別の角度から確かめられる。選択の枠は描いた視点でだけ表示し、オプションバーの「選択した視点に戻る」でその視点に戻れる。描いている途中の矩形や閉じていない多角形は、視点を変えると解除される。オプションバーで対象の側と「移動先」のレイヤー（既定は「削除」、なければ作る）を選び、「選択した点を移動」（Delete）を押す。表示中のスキャンの、表示中のレイヤーの点だけが対象で、操作開始時のカメラを使用し、画面に出ていない原解像度点も判定する。
   - 「範囲内」: 選択範囲を通して見える点を移す。既定ではCloudCompareの分割と同様に無限遠まで（カメラの後方は除く）を対象とし、「範囲外」とちょうど逆の結果になる。「奥行きを制限」を有効にすると、選択範囲にある最も手前の有効な原解像度点を基準に、カメラ前方へ指定した厚さまでに限る。点群内を移動しながら目の前のノイズを消す用途。
   - 「範囲外（切り出し）」: 奥行きを使わず、選択範囲を通して見えない点（範囲外とカメラの後方）をすべて移す。切り出しの用途。
   - 移動予定の表示点を赤で表示する。奥行きを制限する場合は基準点をバックグラウンドで原解像度から求め、求まった後の赤表示は確定結果と一致する。
7. 「3Dボックス選択」（B）では、箱の矢印をドラッグして共通座標のXYZ軸に沿って移動し、青い四角をドラッグして水平面内で移動し、輪をドラッグして箱の中心まわりに回転する。移動・回転とサイズ変更の取っ手は同時に表示する。各面の四角い取っ手をドラッグすると、反対側の面を固定したまま大きさを変えられる。Escでドラッグ前の箱へ戻す。取っ手以外での左ドラッグはカメラ回転。「箱の中をハイライトする」で箱の外の点も通常表示したまま、箱の中の点を黄色で強調し、箱の移動・回転・サイズ変更に追従する。他のツールに切り替えるとハイライトと箱の表示を解除する。「箱の外を移動（切り出し）」「箱の中を移動」は表示中のスキャンの原解像度点を判定し、選んだレイヤー（既定は「削除」）へ移す。箱と重ならないチャンク（箱の中を移すとき）や箱に収まるチャンク（箱の外を移すとき）は読まない。
8. 「距離計測」（M）で表示点を2点クリックすると、3D距離・水平距離・高低差を表示する。
9. 「位置合わせ」（A）では、プロジェクトツリーで選んだスキャンかフォルダーを動かし、表示中の他のスキャンを基準に合わせる。右のパネルで操作し、動かす側を橙、基準を青で色分けする（切り替え可）。どの段階の結果も、適用するまで画面でプレビューされる。
   - 対応点: 動かす側と基準で同じ場所をクリックすると組になる（順番は自由、どちら側かはクリックした点のスキャンで決まる）。3組以上で「対応点で合わせる」と最小二乗の剛体変換を求め、各組の残差を表示する。
   - ICP: 「ICPで合わせる」で、重なる部分の形状から点と面の距離を最小にする。開始距離（既定0.5m、残っているずれより大きくする）で収束するまで反復し、収束するたびに対応距離を半分にして終了距離（既定0.02m）まで1回の実行で絞る。反復は距離ごとに最大50回。処理用の点は表示用8分木を根から階層ごとに集めて一様に取り、非表示のレイヤーの点は使わない。点の読み込みと法線の計算は実行の最初に1回だけ行う。結果には最後の距離でのRMSと、開始距離で見た重なりの割合を表示し、距離ごとのRMS・重なり・反復回数を開いて確かめられる。狭い距離で対応する点が最初の距離の1/10未満になったら、そこで絞るのをやめて手前の距離の結果を返し、その旨を表示する。重なりが10%未満なら注意を出す。開始距離と終了距離を同じにすると、その距離だけで合わせる。
   - 「適用」でスキャンかフォルダーの追加変換に反映する（元に戻せる）。フォルダーを動かすと中のスキャンが一緒に動き、フォルダーの中のスキャンを動かすときは上位フォルダーの変換を考慮する。未適用の結果があるままツリーで別の項目を選ぶと、適用するか破棄するかを確認する（キャンセルすると選択を戻す）。他のツールに切り替えても結果は残り、位置合わせに戻ると再び表示される。
   - 適用した結果は、方法・RMS・重なり・最後の対応距離・基準のスキャン数・日時と、そのときの位置をスキャンかフォルダーごとにプロジェクトへ記録する（元に戻す・リビジョンにも従う）。ツリーの名前の後ろに、位置合わせ済みは緑のチェック、記録の後に動かした・終了距離まで絞れなかった・ICPの重なりが10%未満のものは注意の印を出し、マウスを載せると内容を表示する。フォルダーへ移すだけなど位置が変わらない操作では記録は崩れない。フォルダーごと合わせたスキャンはフォルダーの記録に従う。
   - 全体を最適化: 1つずつ合わせた後の仕上げとして、表示中のスキャンを、重なる部分がすべてそろうように同時に動かす。重なるスキャンの組すべての点と面の距離をまとめて最小にし、ループの終わりに残るずれを全体に振り分ける。ツリーで選んだスキャン（フォルダーなら中のスキャン）を固定し、選んでいなければ最初のスキャンを固定する。開始距離（既定0.1m）から終了距離（既定0.02m）までICPと同じく絞る。サンプル点数はスキャンごと（既定5万点）。どのスキャンとも重なりのないスキャンは動かさず、固定したスキャンにつながらないスキャンのまとまりは、その中で最も大きいスキャンを固定する。結果はそのまま1回の編集として適用し、元に戻すで取り消せる。
   - 位置合わせの一覧（「ツール → 位置合わせの一覧」かパネルのボタン）: ツリーの順に全スキャン・フォルダーの状態と記録を表で示し、行をクリックするとツリーで選ぶ。直前の全体最適化があれば、重なるスキャンの組ごとの重なり（開始距離で）とRMS（終了距離で、前後）をRMSの悪い順に示す。終了距離に対応する点がない組は「—」。「CSVで保存…」で両方の表をCSV（UTF-8、BOM付き）に書き出す。
10. 「ツール → ボクセル間引き」「ツール → ノイズ除去」「ツール → 統計的外れ値除去（SOR）」は、表示中のスキャンの表示中のレイヤーの点に、スキャンごと（スキャンの座標）に掛かり、判定した点を移動先のレイヤー（既定は間引きが「間引き」、ほかは「ノイズ」）へ移す。点の位置・色・属性は書き換えない。
   - ボクセル間引き: 指定した大きさのボクセルごとに、中心に最も近い元の点を1つ残す。「表示中のスキャンをまとめて間引く」を選ぶと、共通座標の1つのグリッドで全スキャンをまとめて扱い、スキャンの重なる部分でも1ボクセルに1点だけ残す（位置合わせ後、書き出し前の仕上げ用）。Trimbleの5cmでは、スキャンごとの44.6万点に対し、まとめると87.2万点を間引いた（約0.7秒）。
   - ノイズ除去: 探索半径の中にある他の点が最小近傍点数より少ない孤立点を移す。
   - 統計的外れ値除去（SOR）: 近い順に指定数の点までの平均距離を各点で求め、スキャン全体の平均より標準偏差の指定倍以上離れた点を移す（既定はCloudCompareと同じ6点・1σ）。探索範囲（既定0.5m）に指定数の点がない点も移す。全体の統計を求める1回目と判定する2回目で点群を2回読み、点ごとの値はメモリに残さない。
   - スキャンの重なりを整理（「ツール → スキャンの重なりを整理」）: 位置合わせ後、スキャンの重なる場所で点が交互に混ざり、スキャンごとの露出や色味の違いでざらついて見えるのを防ぐ。共通座標の格子（既定10cm）ごとに、最も密に点を取っているスキャンの点だけを残し、ほかのスキャンの点を「重複」レイヤーへ移す。近いスキャンや面を正面から撮ったスキャンほど密なので、スキャン位置がなくても（LAS/LAZ・姿勢のないE57でも）判定できる。密度は周囲の格子と合わせて数える。残すスキャンは格子を8×8×8に分けた小マス（既定1.25cm）ごとに、小マスの中心へ補間した密度で決めるので、スキャンの境目は格子の階段ではなく密度が釣り合う線に沿う。残せるのはその小マスに点があるスキャンだけなので、スキャナー足元の欠けの縁や、疎なスキャンの走査線の隙間は、ほかのスキャンの点で埋まったまま残る。同じ密度ならスキャン位置が近いほう、次にスキャンの順で決める。spbの9スキャン（3.7億点）で約90秒。表示中のスキャンをまとめて判定する。各チャンクの格子ごとの点数を先に数え、判定では隣のチャンクの点を読まない。
   - 動体除去（「ツール → 動体除去」）: 通行人など、あるスキャンにだけ写った物の点を「動体」レイヤーへ移す。スキャン位置（器械点）を持つスキャンごとに、器械点から見た方向（水平角×仰角、既定0.1°のマス）ごとの測った距離の距離画像を作り、別のスキャンの点がその方向で測った距離より許容幅（既定5cm、遠いほどマスの大きさの分を加える）以上手前にあれば、そのスキャンのレーザーが素通りした、つまりそのスキャンを撮ったときそこには何もなかったとみなす。素通りしたスキャンが指定数（既定2）以上ある点だけを移す。磨いた床の映り込みで床下にできた点（ゴースト）や1つのスキャンだけの位置合わせのずれは、たいていそのスキャンだけのものなので、2以上にすると静止物を移しにくい。そのぶん、2スキャンからしか見えない場所の動体は残る。点の密度によらないので、SORやノイズ除去で落とせない、密に写った人も移せる。距離画像は各マスと周囲8マスのうち最も近い距離を使い、物の縁や斜めに見た床・壁を素通りと誤らないようにする。マスはスキャンの角度分解能より粗くする（細かいと計測の隙間を素通りと誤る）。素通りを判定できるのはスキャン位置を持つスキャン（姿勢付きのE57。全スキャンが同じ姿勢を共有するものは除く）だけで、判定される側はどのスキャンでもよい。距離画像も表示中のレイヤーの点だけで作るので、床下のゴーストは先にボックス選択などで別のレイヤーへ移しておく（残っていると、その奥まで測ったとみなして床を移すことがある）。表示中のスキャンをまとめて判定し、位置合わせを済ませてから実行する。ずっと同じ場所にいた人や1つのスキャンからしか見えない場所の物は残り、床に立つ人の足もとは許容幅の分だけ残る。マスより細い物（手すり・椅子の脚など）は移ることがあるので、移した点を確かめてから書き出す。距離画像は0.1°で1スキャン約26MBで、処理メモリの半分に収まる数ずつまとめて作り、まとめるごとに全点を判定する。
   - いずれもチャンクの境界をまたいで隣のチャンクの点も見るため、結果はチャンクの分け方に左右されない。非表示のレイヤーの点は判定に使わない。パラメーターは次回も引き継ぐ。
11. すべての点はいずれか1つのレイヤーに属する。取り込んだ点は「点群」に入り、上の操作は点を消さずに別のレイヤーへ移す。操作が新しく作るレイヤーは非表示で始まる。左の「レイヤー」でチェックを外したレイヤーの点は、表示・選択・処理・書き出しのどれにも使わない。右クリックで名前の変更、「すべての点を移動」（例: 「ノイズ」の点を全部「点群」へ戻す）、レイヤーの削除（点は「点群」へ戻る）ができる。一部だけ戻すときは、移した先のレイヤーを表示し、範囲選択で移動先に「点群」を選んで移す。「新しいレイヤー」で自分用のレイヤー（地面・建物など）も作れる。
12. 編集は元に戻す（Ctrl+Z）・やり直す（Ctrl+Y / Ctrl+Shift+Z）ができる。編集のたびに未保存の作業状態をプロジェクトへ書き込むため、終了や異常終了の後も続きから再開できる。
13. 「ファイル → 保存」（Ctrl+S）で名前を指定し、作業状態を新しいリビジョンとして保存する。レイヤーの表示切り替えなど個々の編集ではリビジョンは増えない。「ファイル → リビジョン一覧」で保存済みリビジョンをgitグラフのように表示し（線形の履歴は1本の線、分岐は別の列）、開く・名前の変更・削除ができる。プロジェクト作成時点の空のリビジョンは一覧に表示しない。表示対象のリビジョンが複数あるか未保存の作業があるプロジェクトを開くと、一覧を表示して選ばせる。「未保存の変更」も選択して開ける。過去のリビジョンを開いて編集・保存すると新しい枝になる。未保存の変更があるときに別のリビジョンを開くと、破棄の確認を出す。
14. 「履歴のクリーンアップ」で、どの保存済みリビジョンと作業状態からも使われていないスキャン・点のレイヤー情報・一時ファイルを削除してディスク容量を空ける。不要なリビジョンは先に一覧で削除しておく。元に戻す履歴は消える。
15. 「書き出し」でファイル形式にE57を選ぶと、現在の状態（未保存の変更を含む）の全スキャンの、表示中のレイヤーの点でE57を作る。スキャンのposeにはフォルダーと自身の追加変換を合成し、対応画像にも同じ変換を適用する。スキャンの表示チェックは書き出し対象を変えない（レイヤーの表示は変える）。既存ファイルへの上書きは受け付けない。
16. 「書き出し」でファイル形式にLASまたはLAZを選ぶと、同じく表示中のレイヤーの点を、フォルダーと自身の変換を適用した共通座標で、1つのファイルにまとめるか、スキャンごとに選んだフォルダーへ書き出す（ファイル名はスキャン名）。強度と色は元の属性の値域から16ビットに換算する（LAS由来は元の値のまま、8ビット色は×257）。座標の分解能は0.1mm（範囲が約200kmを超える場合は粗くする）。座標系（WKT）を持つスキャンはLAS 1.4（点形式7、色なしは6）でWKTを保持し、持たない場合は互換性の高いLAS 1.2（点形式2、色なしは0）にする。座標系の異なるスキャンを1ファイルにまとめるとエラーにする。既存ファイルは上書きしない。

長時間処理はバックグラウンドで実行し、キャンセルできる。複数ファイルの取り込みはファイル単位で作業状態へ反映するため、後続の取り込みをキャンセルしても先に完了したファイルは残る。

プロジェクトはフォルダーごと持ち運べる。取り込み済みの元ファイルは再度参照しない。

## 対応範囲

- E57: 色を持たないスキャンは強度を灰色で表示する。取り込み時にスキャンの先頭50万点から強度の1〜99%の範囲を求めて濃淡を割り当てる（宣言された範囲より実際の値がずっと狭いことが多いため）。表示色だけの変更で、元の強度値は変えない。既存のプロジェクトは取り込み直すと反映される。
- E57: 元の数値属性を型ごとに保持する。RGB、強度、row/column、scaled integer、無効点レコードも保持する。scan poseとimage poseを独立して保存し、画像・投影パラメーター・マスク・スキャンとのGUID対応を引き継ぐ。再着色と画像の取り出しUIはまだない。
- LAS/LAZ: XYZ、強度、RGBに加え、分類、リターン、分類フラグ、スキャン角、scanner channel、user data、point source ID、GPS時刻、NIR、Extra Bytesを保持し、LAS/LAZへ書き戻す。VLR/EVLR（Extra Bytes定義、GeoTIFF/WKT、GPS時刻の種類を含む）も保持する。RGB表示は16ビット色を前提とする。波形パケット付きLAS/LAZは、関連データを保持できないため取り込みを拒否する。旧版で省略した属性は取り込み直すまで復元されない。LAS固有属性はE57へは書き出さず、書き出し画面に注意を表示する。

LAS/LAZを1つにまとめる際に属性定義が違う場合は、書き出し画面で「不一致の属性・付加情報を除いてまとめる」を選べる。除外するExtra Bytes・GPS時刻・座標系情報・VLR/EVLRを事前表示し、互換性のある属性は残す。Extra Bytesは定義や長さが違えば全体を除き、GPS時刻は方式が違えば除く（出力形式で必須なら0に置換）。座標系情報を除いても座標は自動変換しない。元のプロジェクトは変更されない。すべての属性を残したい場合は「スキャンごとに別のファイル」を選ぶ。
- 原解像度チャンクは最大65,536点・最大32 MiB。全点をRAMに展開せず、インデックス構築・範囲判定・書き出しをチャンク単位で行う。
- 原解像度はチャンクごと、表示用8分木はノードごとにbyte shuffle + Zstd level 1で可逆圧縮する。圧縮して増えるブロックは無圧縮で保存する。元の属性のbit列、点ID、点ごとのレイヤーとの対応は変わらない。
- 取り込み時のE57点属性変換、チャンクの圧縮と、チャンクの下の表示用8分木の構築を並列処理する。ワーカー数はCPU数−1（最小1・最大8）、処理中と書き込み待ちの変換バッファーは既定256 MiBの予約枠で制限する。アプリ全体のRAM上限ではない。空間分割、読み出し、書き込み、チャンクより上の表示用8分木の構築は直列。詳細は[内部形式の並列取り込み](docs/internal-format.md#並列取り込み)を参照。
- 点のRGBはsRGBとして表示する。経路は[Potreeメモ](docs/potree-rendering-notes.md#rgbの表示経路)を参照。alphaは色変換しない。
- 点群は、処理用の原解像度チャンク（範囲選択・フィルター・位置合わせ・書き出しに使う）と、表示用の8分木の2つで持つ。表示用8分木はPotree 2と同じ足し算型で、全点がどれか1つのノードに1回だけ入り、上のノードから順に足すと密度が上がる。座標・色・元の点への参照だけを持ち、Trimbleの848万点で点データ203 MBに対し111 MB。
- 描画上限の既定は200万点で、画面から調整できる。表示はPotreeと同じく、画面上で大きいノードから描画点数に収まるまで選び、キャッシュにないノードだけを読み込みながら少しずつ表示する。読み込んだノードはGPUに常駐させ、カメラを動かしても点を減らさず、新しく見えた部分だけを足す。展開済みノードのキャッシュとGPUの常駐は、どちらも描画点数の2倍の点まで（キャッシュは1点40バイト、GPUは1点20バイト）。キャッシュはスキャンのローカル座標で持つため、位置合わせの適用ではディスクから読み直さない（点のレイヤーやレイヤーの表示が変わると破棄する）。GPUではスキャンごとの変換を描画時に掛けるため、変換の入力・適用・元に戻すは次の読み込みを待たずに表示へ反映する。
- 非表示点のマスクと空ノードの管理領域も表示キャッシュの予算に含め、点と共通のLRUで追い出す。ノード／チャンクのメタデータはRAMに保持する。RAM/VRAMに応じた表示予算の自動調整は今後の実装。
- フィルターの処理メモリ予算は既定768 MiB。画面で128〜4,096 MiBを指定でき、次回も保持する。予算の1/4をチャンクキャッシュへ配分し、残りとチャンクの展開サイズから並列数を決める（自動は最大16）。ノイズ除去とSORの近傍探索は、チャンクごとのkd-treeを予算内で使い回し、各点はまず自分のチャンクを探して、探索の球がチャンクの外に出る点だけ隣のチャンクを探す。チャンクの周りの探索範囲の点をまとめて集めないので、探索範囲がチャンクより大きい密なスキャンでも時間が探索範囲にほぼ依らない。結果は以前の方式と一致する。結果もワーカー数の2倍のチャンクごとにラベルへ書く。メタデータ、表示、allocator、圧縮ライブラリ内部の領域などは別に使用するため、アプリ全体のRAM上限ではない。

## 未実装・制約

複数スキャンの一括位置合わせ（グラフ最適化）、統合点群（間引いた結果を新しいスキャンとして保存）、LAS/LAZの波形パケット、画像再着色、処理の途中再開は未実装。履歴はリビジョン単位の削除と未使用データのクリーンアップまで実装し、複数リビジョンの集約は未実装。

編集で書き直すのは履歴を持つ`project.json`だけで、チャンクや空間ノードを含むスキャンのメタデータと、点のレイヤー（ラベル）の変更分は別ファイルへ一度だけ書く。メタデータ全体は引き続きRAMに保持する。プロジェクト形式は初版（形式バージョン1）として、公開までは互換性を保証せずに変更している。形式バージョン1でないプロジェクトは取り込み直す。LAS属性追加前の形式1は読み込めるが、省略済みの属性を復元するには元ファイルから取り込み直す。

点を移した後の表示用8分木は作り直さない。表示の予算は、各ノードの表示中の点数の見積もり（ノードが持つチャンクごとの点数と、チャンクごとのレイヤー別点数から求める）で数えるため、間引きや切り出しで大きく減ったスキャンも深い階層から上限まで描く。すべて非表示になったノードは読まない。

現在の座標単位はメートルを前提とする。単位変換・座標参照系の変換は行わない。異なる座標メタデータのスキャンを一つのE57に書き出す場合はエラーにする。

E57の保存対象は利用ライブラリが解釈できる点属性・標準メタデータ・画像。元XMLを監査用に保存するが、独自のXML構造を含むファイル全体の完全な再現は保証しない。元の点順序は空間分割で変わる。同じGUIDを持つ入力の重複取り込みについては、書き出し時のGUID再割り当てが今後必要。

プロジェクトを開いている間は`project.lock`をOSで排他ロックし、別プロセスから開く操作を拒否する。UI・ワーカー・同じプロセス内の再読み込みはロックを共有する。強制終了してもOSがロックを解放するため、残ったロックファイルを手動削除する必要はない。旧版はこのロックを使用しないため、同じプロジェクトを旧版と同時に開かない。キャンセルや失敗で残る`staging/`・未参照データは「履歴のクリーンアップ」で削除する（自動では消さない）。元ファイルを含むディスク容量と、一時的な作業容量が必要。

Zstd導入後の実データの資産容量（点・表示用LOD・画像・元XML、manifestを除く。表示用8分木の導入前）は、manitouが104.1 MB→34.4 MB、Trimbleが684.5 MB→220.4 MB。既存プロジェクトのコピーを変換して検証した。

取り込みの並列化後、Trimbleの848万点を同じPCのRelease版で計測した。変更前は約12.6秒、変更後は1ワーカーで約9.5秒、8ワーカーで約7.2〜7.6秒。並列化に加えてLOD候補の全点ソートを省いた改善を含む。ローカルディスク／OSキャッシュの影響がある実測値で、ストレージや点属性によって変わる。変更前のプロジェクトと全原解像度チャンク・点参照・木構造・全LODを照合した。画像入りmanitouでも同じ照合を行った。

点群処理と書き出しも同じTrimble（848万点）のRelease版で計測した。5cmのボクセル間引きが約1.0秒、続けて半径0.1m・4点未満のノイズ除去が約1.6秒、SOR（6点・1σ、間引き前）が約3.2秒（どちらもスキャンごと・最大16スレッド）。全点のLAS書き出しが約2.7秒（221 MB）、LAZが約4.6秒（104 MB）。

ICPは`align_bench`で、各スキャンに既知のずれ（スキャン中心周りに約1.8°と15cm）を与えて他のスキャンに合わせ直して確かめられる。manitou（5スキャン、E57から取り込み直したもの）では開始距離0.5m・終了距離0.02mで、重なり45〜69%の4スキャンがスキャン範囲の隅で0.5〜1.1cm以内に戻り、1スキャン約0.6秒（0.5mの1段だけでは10〜20cm）。重なり11%のスキャンは合わない（2026-10-05）。ずれなしから始めてもICPの解は元の位置合わせから1〜4cm動くため、これが比較の下限になる。重なりが5%程度のスキャンは合わない。

```powershell
cargo run -p geemil-core --release --example align_bench -- work-data/manitou 0.5 1
# 終了距離は6番目の引数（既定0.02）。開始距離と同じにすると1段だけで合わせる
cargo run -p geemil-core --release --example align_bench -- work-data/manitou 0.5 1 60000 50 0.5
```

全体の最適化は`global_bench`で、最初のスキャン以外に、後のスキャンほど大きいずれ（1スキャンごとに約0.1°と1cmずつ増える）を与えて、最初のスキャンを固定して合わせ直して確かめられる。プロジェクトは一時フォルダーへ複製して扱い、元は変更しない。manitouでは、ずれを与えた場合も与えない場合も同じ解（差は約1cm以内）に収まり、組ごとのRMSの平均は6.8mmから5.6mmに下がった（約5秒）。実データには正解がないため、隅の誤差は元の位置合わせとの差を表す。

```powershell
cargo run -p geemil-core --release --example global_bench -- work-data/manitou 1
```

### 1億点での実測

現形式のレイヤー、LAS属性保持、メモリ予算付きフィルターでの再検証は[2026-10-04の性能検証](docs/performance-review-20261004.md)を参照。現版のReleaseビルドで1億点を取り込み直し、間引き・ノイズ除去・Undo/Redo・1,200視点のCPU表示更新・LAS/LAZ書き出しまで通した。

以下は、点のレイヤーを導入する前（除外レイヤーをビットマスクで持っていた版）の過去の計測値。現在の性能値やメモリ上限としては扱わない。

`make_synthetic`で地上レーザー風の合成データ（10スキャン×1,000万点のLAS、計2.5 GB。スキャナー位置から角度一様に光線を出し、地面・円形の壁・箱に当たった点。近いほど密）を作り、同じPC（Core i5-12400F、RAM 64 GB、RTX 3060、Release版）で測った。メモリは各プロセスのピークのワーキングセット。

| 処理 | 時間 | ピークメモリ |
| --- | ---: | ---: |
| 取り込み（10ファイル、1億点） | 186秒 | 78 MB |
| 表示（200万点の読み込み、起動から） | 0.19秒 | 414 MB（GUI全体） |
| ボクセル間引き 2 cm（7,042万点を移動） | 28秒 | 493 MB |
| ノイズ除去 半径5 cm・4点未満（609万点を移動） | 26秒 | 271 MB |
| LAS書き出し（残り2,349万点、0.57 GB） | 35秒 | 23 MB |
| LAZ書き出し（同、0.25 GB） | 39秒 | 26 MB |
| ICP（1スキャン、6万サンプル） | 約0.25秒 | 19 MB |

- プロジェクトのディスク使用量は3.1 GB（元のLASは2.5 GB）。取り込み中は1ファイル分の展開データ（1,000万点で約0.9 GB）を一時的に`staging`へ置く。
- 当時の表示のGPUメモリは、点の頂点バッファー（200万点×28バイト＝約56 MB）と画面サイズの描画先が中心。現版はノード単位の常駐バッファーとキャッシュを使う。
- メモリは点数ではなくチャンク・キャッシュの予算で決まり、1億点でも数百MBに収まった。処理時間はほぼ点数に比例する。
- この合成シーンは円形の壁と規則的な箱の並びで回転方向の手がかりが少ないため、ICPの精度評価には向かない（ずれなしから始めても隅で最大1 m動く）。精度は実データのmanitouで確認している。

```powershell
cargo run -p geemil-core --release --example make_synthetic -- work-data/syn100m 10 10000000
cargo run -p geemil-core --release -- import work-data/syn100m-p (Get-ChildItem work-data/syn100m/*.las)
```

工程表示ごとの経過時間と取り込み全体を測るには、未作成の出力フォルダーを指定する。第3引数はワーカー数（0は自動）、第4引数は変換バッファーの予算MiB、第5引数は任意の比較用プロジェクト。工程の処理は重なるため、表示された時間は各工程の単独CPU時間ではない。

```powershell
cargo run -p geemil-core --release --example import_bench -- Trimble_StSulpice-Cloud-50mm.e57 work-data/bench-8 8 256
```

CPU側の読み込みは、`view_bench`で同じ周辺を少しずつ回転して計測できる。GPU転送・描画は含まない。Trimbleの約20万点では、導入前のDebug版が毎回約122〜131ms、キャッシュ導入後のDebug版は再利用時約7〜9ms。圧縮後のRelease版は初回約21ms、再利用時約1.5〜1.8msだった。ディスク読み込み・展開・座標変換の初回コストは残る。DebugとReleaseの数字を同じ条件の高速化率として比較しない。

表示用ノードの読み込み・解凍・点への復元は、CPU数−1（最大8）のワーカーで並列化する。処理中・完了待ちのノードと展開用の一時メモリには256 MiBの上限を設け、キャッシュ済みノードを先に表示する。全レイヤー表示時は点ごとの非表示判定を省く。`view_bench PROJECT BUDGET WORKERS`のWORKERSは0で自動、1で直列。ノード選択と読み込み時間を別々に出力する。Manitouの326ノード・約110万点では、Release版の初回CPU読み込みが変更前の約143msから自動ワーカーで約24〜34msになった（ディスクキャッシュの影響を含む）。GUI自動テストはCPU結果受信までと全GPU転送の投入までを記録し、GPU処理完了・画面への提示時間とは区別する。

```powershell
cargo run -p geemil-core --release --example view_bench -- work-data/trimble
```

点数ではなくスキャン数・編集回数で増える処理は`scale_bench`で計測できる。初回は指定したLASフォルダーからプロジェクトを作り、スキャンをフォルダーに分け、指定回数の小さな範囲選択の移動でラベルのパッチを作る（2回目以降は作成済みのプロジェクトを使う）。スキャン一覧、ツリーのフォルダー集計、表示ノードの選択（キャッシュなし・あり）とノード読み込みの時間を出力する。300スキャン（各3万点）・20フォルダー・パッチ199件で、表示更新ごとのノード選択は約3.4msから約2.7ms、キャッシュ済みノードの読み込みは約9〜10msから約0.4〜1.5msになった。各点群チャンクのレイヤー別点数はプロジェクトの状態ごとに一度だけ求めるため、チャンクの多い大規模データほど差が大きくなる。

```powershell
cargo run -p geemil-core --release --example make_synthetic -- work-data/syn-scale-las 300 30000
cargo run -p geemil-core --release --example scale_bench -- work-data/syn-scale-proj work-data/syn-scale-las 20 200
```

選択範囲の移動は`selection_bench`で計測できる。初期の全体表示で画面中央の正方形（第2引数は半幅、0.5で画面全体）を奥行き（第3引数、m）付きで「Deleted」レイヤーへ移す。プロジェクトを書き換えるため、コピーに対して実行する。原解像度チャンクのうち選択範囲・奥行きに入り得ないものは読み込まない。以下はレイヤー導入前の計測値。Trimbleの848万点のRelease版で、チャンクを読み飛ばす変更の前は範囲によらず約2.4秒、変更後は中央の小範囲で約0.5秒、画面全体・奥行き0.5mで約0.75秒、全点で約1.2秒。結果は変更前とbit単位で一致した。

```powershell
cargo run -p geemil-core --release --example selection_bench -- work-data/trimble-copy 0.05 0.5
```

第3引数を`inf`にすると奥行きを制限しない。第4引数に`outside`を指定すると範囲外（切り出し）を計測する。同じ848万点で中央の正方形（半幅0.15）の外側26.7万点は約0.8秒、内側821.7万点の奥行き無制限は約0.85秒で、両者の合計は全点数と一致した。

開発用のGPU起動テストでは、2秒間カメラを回転・平行移動し、移動中にもノードの更新が完了することを確認して画面を保存する。


移動プレビューの確認では、起動1秒後に画面中央を矩形選択し、赤表示の点数と基準点を出力して画面を保存する。`inside`は奥行き0.5mの範囲内、`inside-all`は奥行き無制限の範囲内、`outside`は範囲外。

`--smoke-script`は、表示の読み込み後に操作を順に実行し、各操作後のスキャン数・フォルダー数・レイヤーごとの点数・リビジョン数・未保存の有無・元に戻す／やり直すの可否を出力する。操作は`exclude`（選択した点を「削除」へ移す）・`undo`・`redo`・`save`・`folder`・`remove`・`measure`・`preview`（最初のスキャンの変換を入力するが適用しない。動いた表示点数を出力する）・`apply-transform`（入力中の変換を適用する）・`subsample`（5cmのボクセル間引き）・`noise`（半径0.1m・4点未満のノイズ除去）・`sor`（6点・1σの統計的外れ値除去）・`subsample-merged`（表示中のスキャンをまとめて5cmで間引き）・`align-icp`（最初のスキャンを他のスキャンにICPで合わせてプレビュー）・`align-pairs`（一致する4組の対応点で合わせ、動かないことを確認）・`align-global`（最初のスキャンを固定して全体を最適化）・`align-list`（位置合わせの一覧を開き、済み・要確認・未実施の数と全体最適化の前後のRMSを出力）・`align-switch`（最後のスキャンを選び、未適用の結果の確認が出たかを出力）・`align-leave`（「カメラ操作」ツールへの切り替えを試み、未適用の結果の確認が出たかを出力）・`align-apply`（プレビュー中の結果を適用）・`ortho`（平行投影の上面図）・`box`（表示点の中央の高さに2mの水平スライスを置き内部をハイライト、箱の中の表示点数を出力）・`box-resize`（傾けた箱でサイズ変更の取っ手を表示）・`box-crop`（その箱の外を「削除」へ移す）・`transform`／`transform-folder`（最初のスキャンかフォルダーを選び「移動・回転」ツールにする）・`place-handles`（画面中央をダブルクリックしたものとして取っ手を置き、前後の位置を出力）・`show-layers`（すべてのレイヤーを表示）・`restore`（最も新しいレイヤーの点を全部「点群」へ戻す）・`color-height`／`color-scan`（色の表示方法）・`adaptive`（点サイズを適応にする）・`focus`（最初のスキャンにカメラを寄せる）・`zoom`（カメラ距離を1/8にする）。各操作の行は操作を始めた時点の状態で、バックグラウンド処理（`job true`）の結果は次の行に出る。`--smoke-dialog`には`subsample`と`noise`も指定できる。`--smoke-budget N`で描画点数を変えられる（例: `--smoke-orbit --smoke-budget 20000000`）。プロジェクトを書き換えるため、コピーに対して実行する。

```powershell
cargo run -p geemil-desktop --release -- work-data/manitou-copy --smoke-test work-data/flow.png --smoke-select inside-all --smoke-script exclude,undo,redo,folder,save,remove,measure
```

Potreeのカメラ・ノード表示処理の参照結果と色修正の詳細は[docs/potree-rendering-notes.md](docs/potree-rendering-notes.md)にまとめている。

### 現形式の連続処理・長時間表示の検証

`workflow_bench`は新しいプロジェクトを作り、取り込み、2cm間引き、Undo/Redoを20往復、半径5cm・4点未満のノイズ除去、指定数の視点のCPU表示更新、LAS/LAZ書き出しを連続して実行する。入力と既存プロジェクトは変更しない。出力にはWindowsのプロセスメモリ・staging容量の50msごとの観測ピークと、CPU表示更新のp50/p95/p99を含む。短い工程ではサンプリングがピークを見逃すため、プロセス起動以降のOS累積ピークも記録する。GPU描画や画面提示の時間は含まない。

```powershell
cargo run -p geemil-core --release --example workflow_bench -- work-data/bench-current work-data/syn100m 1200
```

GUIの長時間検証はPowerShell 7で行う。`--smoke-orbit-seconds`は回転・平行移動の時間を指定し、対象から離れない経路を使う。`scripts/measure-gui.ps1`はRAMとWindowsのGPUプロセスメモリカウンターを約500ms間隔で記録し、PNG・ログ・metrics JSONを保存する。GPUカウンターが取得できなければ値はnullとなる。フレーム間隔はUI callbackの観測値で、GPU fenceや画面提示を直接測定した値ではない。既存の出力PNGは上書きしない。`-SmokeScript`で編集を実行する場合はコピーしたプロジェクトに対して使う。

```powershell
cargo build -p geemil-desktop --release
.\scripts\measure-gui.ps1 -Project work-data/bench-current -OutputPrefix work-data/bench-gui -OrbitSeconds 120
```
