# Geemil Workbench

Windows向けのOSS点群編集アプリ。Rust / egui / wgpuで、原解像度の点をディスクに保持し、表示用LODを必要に応じて読み込む。設計方針は[docs/design.md](docs/design.md)、現在の内部形式は[docs/internal-format.md](docs/internal-format.md)を参照。

現在は、取り込みから手動編集、E57への書き出しまでを試すための初期プロトタイプ。プロジェクト形式は暫定版で、将来の版との互換性は未確定。

## 起動

WindowsのRust MSVC環境とC++ Build Toolsが必要。開発時の確認環境はRust 1.94.0。初回ビルドは依存ライブラリをダウンロードする。

```powershell
cargo run -p geemil-desktop --release
```

既存のプロジェクトフォルダーを指定して起動できる。

```powershell
cargo run -p geemil-desktop --release -- work-data/trimble
```

WindowsではDirectX 12を既定とする。`WGPU_BACKEND`環境変数でバックエンドを指定できる。画面の日本語フォントはWindowsのメイリオ／游ゴシックを使用し、配布物には同梱しない。

## 操作

1. 「新規プロジェクト」で、まだ存在しないフォルダー名を指定する。
2. 「点群を取り込む」でE57、LAS、LAZを選択する。複数ファイルを選択できる。E57は`data3D`ごと、LAS/LAZはファイルごとに独立したスキャンとなる。
3. 「カメラ操作」では左ドラッグでカメラターゲットを中心に回転、右／中ドラッグで平行移動、ホイールでズームする。ダブルクリックした位置の表示点を回転中心にする。スキャンのチェックで表示対象を切り替える。「陰影強調（EDL）」で奥行きの段差に陰影を付ける。
4. 「矩形選択」では左ドラッグ、「多角形選択」では左クリックで頂点を追加し、ダブルクリックかEnterで閉じる。Escで選択を解除する。カメラを動かすと選択は解除される。
5. 除外する側を選び、「除外を実行」（Delete）を押す。表示対象スキャンだけが対象で、操作開始時のカメラを使用し、LODに出ていない原解像度点も判定する。
   - 「範囲内を除外」: 選択範囲にある最も手前の有効な原解像度点を基準に、カメラ前方へ「奥行き」で指定した厚さまでを除外する。点群内を移動しながら目の前のノイズを消す用途。
   - 「範囲外を除外」: 奥行きを使わず、選択範囲を通して見えない点（範囲外とカメラの後方）をすべて除外する。切り出しの用途。
   - 除外予定の表示点を赤で表示する。範囲内の除外では基準点をバックグラウンドで原解像度から求め、求まった後の赤表示は確定結果と一致する。
6. 除外レイヤーのチェックで除外を解除・再適用できる。「履歴」で過去の状態へ切り替え、分岐名を入力してフォークできる。過去の状態から直接編集しても新しい枝になる。
7. 「位置合わせ（追加変換）」で選択中のスキャンの平行移動量・XYZ回転角を入力し、「変換を確定」を押す。ファイル座標系で元のposeに追加する剛体変換で、元の点は書き換えない。対応画像にも同じ追加変換を適用して書き出す。
8. 「E57書き出し」で、現在のリビジョンの全スキャンから除外点を取り除いたE57を作る。表示チェックは書き出し対象を変えない。既存ファイルへの上書きは受け付けない。

処理完了ごとにプロジェクトを自動保存する。長時間処理はバックグラウンドで実行し、キャンセルできる。複数ファイルの取り込みはファイル単位で確定するため、後続の取り込みをキャンセルしても先に完了したファイルは残る。

プロジェクトはフォルダーごと持ち運べる。取り込み済みの元ファイルは再度参照しない。

## 対応範囲

- E57: 元の数値属性を型ごとに保持する。RGB、強度、row/column、scaled integer、無効点レコードも保持する。scan poseとimage poseを独立して保存し、画像・投影パラメーター・マスク・スキャンとのGUID対応を引き継ぐ。再着色と画像の取り出しUIはまだない。
- LAS/LAZ: XYZ、強度、RGBを取り込む。RGB表示は16ビット色を前提とする。GPS時刻、Extra Bytes、分類、リターン情報など、現在保持しない属性はスキャンの「取り込み時に省略した属性」に表示する。
- 原解像度チャンクは最大65,536点・最大32 MiB。全点をRAMに展開せず、インデックス構築・範囲判定・書き出しをチャンク単位で行う。
- 原解像度はチャンクごと、LODはノードごとにbyte shuffle + Zstd level 1で可逆圧縮する。圧縮して増えるブロックは無圧縮で保存する。元の属性のbit列、点ID、除外マスクとの対応は変わらない。
- 取り込み時のE57点属性変換、leafのLOD生成・点／LOD圧縮を並列処理する。ワーカー数はCPU数−1（最小1・最大8）、処理中と書き込み待ちの変換バッファーは既定256 MiBの予約枠で制限する。アプリ全体のRAM上限ではない。空間分割、読み出し、書き込み、親LOD構築は直列。詳細は[内部形式の並列取り込み](docs/internal-format.md#並列取り込み)を参照。
- 点のRGBはsRGBとして表示する。点シェーダーでリニア化し、sRGB対応の描画テクスチャをeguiへ渡す。alphaは色変換しない。
- 描画上限の既定は20万点で、画面から調整できる。移動中は最大32,000点で更新し、150ms静止したら詳細化する。展開済みノードのキャッシュは既定256 MiB。カメラ移動時はノードとGPUバッファーを再利用する。
- ノード／チャンクのメタデータはRAMに保持する。GPUへのノード単位の常駐管理、RAM/VRAMに応じた自動調整は今後の実装。

既存の無圧縮プロジェクトも引き続き開ける。「内部データを圧縮」で、履歴や除外を保持したまま旧形式の点とLODを圧縮できる。新データを全ブロック読み戻して照合してから確定し、旧資産を削除する。変換中は新旧データを同時に置くディスク容量が必要。

## 未実装・制約

ICP、ノイズフィルター、ボクセル間引き、統合点群、3Dボックス切り出し、LAS/LAZ書き出し、画像再着色、履歴の削除・GC、処理の途中再開は未実装。

取り込み後の除外は原解像度点にも反映するが、除外後のLOD再生成は未実装。遠景では代表点が減り、表示密度が下がる場合がある。プレビューは書き出し結果そのものではない。

現在の座標単位はメートルを前提とする。単位変換・座標参照系の変換は行わない。異なる座標メタデータのスキャンを一つのE57に書き出す場合はエラーにする。

E57の保存対象は利用ライブラリが解釈できる点属性・標準メタデータ・画像。元XMLを監査用に保存するが、独自のXML構造を含むファイル全体の完全な再現は保証しない。元の点順序は空間分割で変わる。同じGUIDを持つ入力の重複取り込みについては、書き出し時のGUID再割り当てが今後必要。

同一プロジェクトを複数プロセスから同時編集するための排他制御は未実装。キャンセルや失敗で残る`staging/`・未参照データの自動整理も今後実装する。元ファイルを含むディスク容量と、一時的な作業容量が必要。

## CLIと検証

```powershell
cargo run -p geemil-core --release -- import work-data/trimble Trimble_StSulpice-Cloud-50mm.e57
cargo run -p geemil-core --release -- inspect work-data/trimble
cargo run -p geemil-core --release -- compress work-data/trimble
cargo run -p geemil-core --release -- export work-data/trimble work-data/trimble-roundtrip.e57
cargo run -p geemil-core --release --example verify_e57 -- Trimble_StSulpice-Cloud-50mm.e57 work-data/trimble-roundtrip.e57
```

`verify_e57`は未編集の書き戻しを検証するためのツール。点順序によらない数値属性のハッシュ集計、点数、schema、scan pose、image pose、画像対応、投影パラメーター、画像・マスクのハッシュを照合する。全点をメモリに格納しない。ハッシュ照合は暗号学的な完全一致証明ではない。

小さな検証用E57を生成するコマンドもある。

```powershell
cargo run -p geemil-core -- demo work-data/demo.e57
```

```powershell
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
```

12件の結合テストと3件の単体テストで、複数スキャンと複数画像の保持、pose、元ファイルなしの再開、原解像度での奥行き選択、除外、分岐・切り替え、処理途中のキャンセル、LAS/LAZ取り込み、少ない描画枠での複数スキャン表示、球面座標・scaled integer・無効点・大きな整数属性を検証する。加えて、旧形式からの圧縮変換、変換中断、キャッシュ再利用、リビジョンによる無効化、浮動小数点のbit保持、圧縮データの破損検出、ワーカー処理の重なりと出力順序、完了結果のメモリ予約、ワーカーエラー、1／4ワーカーでの出力一致、インデックス構築中の中断、同一点の大量重複を検証する。

ローカル実データでも取り込みと未編集E57の書き戻しを照合した。

| データ | スキャン | 点数 | 画像 | 確認 |
| --- | ---: | ---: | ---: | --- |
| manitouNoInvalidPoints.e57 | 5 | 1,095,702 | 5 | 元の点属性、スキャン・画像pose、投影・画像データ |
| Trimble_StSulpice-Cloud-50mm.e57 | 5 | 8,484,455 | 0 | RGBを含む元の点属性、スキャンpose、DirectX 12表示 |

この規模での確認は、億点以上の性能検証を置き換えるものではない。次の段階で大規模データの処理時間・RAM・一時ディスク使用量を計測する。

Zstd導入後の実データの資産容量（点・LOD・画像・元XML、manifestを除く）は、manitouが104.1 MB→34.4 MB、Trimbleが684.5 MB→220.4 MB。既存プロジェクトのコピーを変換して検証した。

取り込みの並列化後、Trimbleの848万点を同じPCのRelease版で計測した。変更前は約12.6秒、変更後は1ワーカーで約9.5秒、8ワーカーで約7.2〜7.6秒。並列化に加えてLOD候補の全点ソートを省いた改善を含む。ローカルディスク／OSキャッシュの影響がある実測値で、ストレージや点属性によって変わる。変更前のプロジェクトと全原解像度チャンク・点参照・木構造・全LODを照合した。画像入りmanitouでも同じ照合を行った。

工程表示ごとの経過時間と取り込み全体を測るには、未作成の出力フォルダーを指定する。第3引数はワーカー数（0は自動）、第4引数は変換バッファーの予算MiB、第5引数は任意の比較用プロジェクト。工程の処理は重なるため、表示された時間は各工程の単独CPU時間ではない。

```powershell
cargo run -p geemil-core --release --example import_bench -- Trimble_StSulpice-Cloud-50mm.e57 work-data/bench-8 8 256
```

CPU側の読み込みは、`view_bench`で同じ周辺を少しずつ回転して計測できる。GPU転送・描画は含まない。Trimbleの約20万点では、導入前のDebug版が毎回約122〜131ms、キャッシュ導入後のDebug版は再利用時約7〜9ms。圧縮後のRelease版は初回約21ms、再利用時約1.5〜1.8msだった。ディスク読み込み・展開・座標変換の初回コストは残る。DebugとReleaseの数字を同じ条件の高速化率として比較しない。

```powershell
cargo run -p geemil-core --release --example view_bench -- work-data/trimble
```

選択範囲の除外は`selection_bench`で計測できる。初期の全体表示で画面中央の正方形（第2引数は半幅、0.5で画面全体）を奥行き（第3引数、m）付きで除外する。プロジェクトに除外レイヤーを確定するため、コピーに対して実行する。原解像度チャンクのうち選択範囲・奥行きに入り得ないものは読み込まない。Trimbleの848万点のRelease版で、変更前は範囲によらず約2.4秒、変更後は中央の小範囲で約0.5秒、画面全体・奥行き0.5mで約0.75秒、全点除外で約1.2秒。除外マスクは変更前とbit単位で一致した。

```powershell
cargo run -p geemil-core --release --example selection_bench -- work-data/trimble-copy 0.05 0.5
```

第4引数に`outside`を指定すると範囲外の除外（切り出し）を計測する。同じ848万点で中央の正方形（半幅0.15）の外側26.7万点の除外は約0.8秒。

開発用のGPU起動テストでは、2秒間カメラを回転・平行移動し、移動中にもノードの更新が完了することを確認して画面を保存する。

```powershell
cargo run -p geemil-desktop --release -- work-data/trimble --smoke-test work-data/preview.png --smoke-orbit
```

RGB表示の検証では、既知の12色をGPUとeguiを経由して表示し、スクリーンショットのpixel値を入力と照合する。

```powershell
cargo run -p geemil-desktop --release -- --smoke-test work-data/colors.png --smoke-colors
```

除外プレビューの確認では、起動1秒後に画面中央を矩形選択し、赤表示の点数と基準点を出力して画面を保存する。`inside`は範囲内、`outside`は範囲外の除外。

```powershell
cargo run -p geemil-desktop --release -- work-data/trimble --smoke-test work-data/select.png --smoke-select outside
```

Potreeのカメラ・ノード表示処理の参照結果と色修正の詳細は[docs/potree-rendering-notes.md](docs/potree-rendering-notes.md)にまとめている。
