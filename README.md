# Geemil Workbench

Windows向けのOSS点群編集アプリ。Rust / egui / wgpuで、原解像度の点をディスクに保持し、表示用LODを必要に応じて読み込む。設計方針は[docs/design.md](docs/design.md)、現在の内部形式は[docs/internal-format.md](docs/internal-format.md)を参照。

現在は、取り込みから手動編集、E57への書き出しまでを試すための初期プロトタイプ。プロジェクト形式は暫定版で、将来の版との互換性は未確定。

## 起動

WindowsのRust MSVC環境とC++ Build Toolsが必要。Rustの版はリポジトリの`rust-toolchain.toml`で固定している（現在1.99.0、egui 0.36の要件は1.95以上）。rustupが自動で取得する。初回ビルドは依存ライブラリをダウンロードする。

```powershell
cargo run -p geemil-desktop --release
```

既存のプロジェクトフォルダーを指定して起動できる。

```powershell
cargo run -p geemil-desktop --release -- work-data/trimble
```

WindowsではDirectX 12を既定とする。`WGPU_BACKEND`環境変数でバックエンドを指定できる。画面の日本語フォントはWindowsのメイリオ／游ゴシックを使用し、配布物には同梱しない。

## 操作

画面は上からメニューバー、アイコンのツールバー、選択中のツールのオプションバー、左にプロジェクトツリー・プロパティ・除外レイヤー、下にステータスバー。キー操作の一覧は「ヘルプ → キーボードショートカット」にある。

1. 起動画面か「ファイル → 新規プロジェクト」（Ctrl+N）で名前と保存先を指定する。作成後に取り込むファイルを選ぶ。点群ファイルをウィンドウにドロップしても始められる。プロジェクトがなければ作成画面を開き、作成後に取り込む。最近使ったプロジェクトは起動画面とファイルメニューから開ける。
2. 「点群を取り込む」（Ctrl+I）でE57、LAS、LAZを選択する。E57は`data3D`ごと、LAS/LAZはファイルごとに独立したスキャンとなる。複数スキャンを含むE57は、ファイル名のフォルダーにまとめる。
3. 「カメラ操作」（V）では左ドラッグで回転、右ドラッグで平行移動、ホイールでズームする。ダブルクリックした位置の表示点を回転中心にする。全体表示（F）、上面・正面・側面・等角（7・1・3・5）、陰影強調EDL（E）はツールバーと表示メニューにある。描画点数（既定200万点、10万点単位）と点サイズはツールバーで変え、次回起動時も保持する。
4. プロジェクトツリーのチェックで表示を切り替える。フォルダーのチェックは中のスキャンをまとめて切り替える。右クリックで新しいフォルダー・名前の変更・移動先・フォルダーの解除・これだけ表示・プロジェクトから外す。ドラッグ＆ドロップでフォルダーへ移動できる。移動や解除をしても点の位置は変わらない（変換を補正する）。
5. プロパティに点数・元ファイル・対応画像などを表示する。「位置合わせ（追加変換）」でスキャンかフォルダーの平行移動量・XYZ回転角を入力すると、表示中の点がその場で動いてプレビューされる。「適用」で作業状態に反映し、「入力を戻す」で入力を取り消す。フォルダーの変換は中のすべてのスキャンと対応画像に掛かるため、階ごとにまとめたスキャンを最後に建物全体として合わせられる。元の点は書き換えない。
6. 「矩形選択」（R）では左ドラッグ、「多角形選択」（P）では左クリックで頂点を追加し、ダブルクリックかEnterで閉じる。Escで選択を解除する。カメラを動かすと選択は解除される。オプションバーで除外する側を選び、「除外を実行」（Delete）を押す。表示対象スキャンだけが対象で、操作開始時のカメラを使用し、LODに出ていない原解像度点も判定する。
   - 「範囲内を除外」: 選択範囲を通して見える点を除外する。既定ではCloudCompareの分割と同様に無限遠まで（カメラの後方は除く）を対象とし、「範囲外を除外」とちょうど逆の結果になる。「奥行きを制限」を有効にすると、選択範囲にある最も手前の有効な原解像度点を基準に、カメラ前方へ指定した厚さまでに限る。点群内を移動しながら目の前のノイズを消す用途。
   - 「範囲外を除外」: 奥行きを使わず、選択範囲を通して見えない点（範囲外とカメラの後方）をすべて除外する。切り出しの用途。
   - 除外予定の表示点を赤で表示する。奥行きを制限する場合は基準点をバックグラウンドで原解像度から求め、求まった後の赤表示は確定結果と一致する。
7. 「距離計測」（M）で表示点を2点クリックすると、3D距離・水平距離・高低差を表示する。
8. 「ツール → ボクセル間引き」と「ツール → ノイズ除去」は、表示中のスキャンにスキャンごと（スキャンの座標）に掛かり、結果を除外レイヤーとして追加する。点の位置・色・属性は書き換えない。
   - ボクセル間引き: 指定した大きさのボクセルごとに、中心に最も近い元の点を1つ残す。
   - ノイズ除去: 探索半径の中にある他の点が最小近傍点数より少ない孤立点を除外する。
   - どちらもチャンクの境界をまたいで隣のチャンクの点も見るため、結果はチャンクの分け方に左右されない。既に除外された点は判定に使わない。パラメーターは次回も引き継ぐ。
9. 除外レイヤーのチェックで除外を解除・再適用できる。
10. 編集は元に戻す（Ctrl+Z）・やり直す（Ctrl+Y / Ctrl+Shift+Z）ができる。編集のたびに未保存の作業状態をプロジェクトへ書き込むため、終了や異常終了の後も続きから再開できる。
11. 「ファイル → 保存」（Ctrl+S）で作業状態を新しいリビジョンとして保存する。Ctrl+Shift+Sは名前を付けて保存。レイヤーの切り替えなど個々の編集ではリビジョンは増えない。「ファイル → リビジョン一覧」で保存済みリビジョンをgitグラフのように表示し（線形の履歴は1本の線、分岐は別の列）、開く・名前の変更・削除ができる。リビジョンが複数あるか未保存の作業があるプロジェクトを開くと、一覧を表示して選ばせる。過去のリビジョンを開いて編集・保存すると新しい枝になる。未保存の変更があるときに別のリビジョンを開くと、破棄の確認を出す。
12. 「履歴のクリーンアップ」で、どの保存済みリビジョンと作業状態からも使われていないスキャン・除外レイヤー・一時ファイルを削除してディスク容量を空ける。不要なリビジョンは先に一覧で削除しておく。元に戻す履歴は消える。
13. 「E57に書き出す」で、現在の状態（未保存の変更を含む）の全スキャンから除外点を取り除いたE57を作る。スキャンのposeにはフォルダーと自身の追加変換を合成し、対応画像にも同じ変換を適用する。表示チェックは書き出し対象を変えない。既存ファイルへの上書きは受け付けない。
14. 「LAS/LAZに書き出す」で、同じく除外点を取り除き、フォルダーと自身の変換を適用した共通座標で、1つのファイルにまとめるか、スキャンごとに選んだフォルダーへ書き出す（ファイル名はスキャン名）。強度と色は元の属性の値域から16ビットに換算する（LAS由来は元の値のまま、8ビット色は×257）。座標の分解能は0.1mm（範囲が約200kmを超える場合は粗くする）。座標系（WKT）を持つスキャンはLAS 1.4（点形式7、色なしは6）でWKTを保持し、持たない場合は互換性の高いLAS 1.2（点形式2、色なしは0）にする。座標系の異なるスキャンを1ファイルにまとめるとエラーにする。既存ファイルは上書きしない。

長時間処理はバックグラウンドで実行し、キャンセルできる。複数ファイルの取り込みはファイル単位で作業状態へ反映するため、後続の取り込みをキャンセルしても先に完了したファイルは残る。

プロジェクトはフォルダーごと持ち運べる。取り込み済みの元ファイルは再度参照しない。

## 対応範囲

- E57: 元の数値属性を型ごとに保持する。RGB、強度、row/column、scaled integer、無効点レコードも保持する。scan poseとimage poseを独立して保存し、画像・投影パラメーター・マスク・スキャンとのGUID対応を引き継ぐ。再着色と画像の取り出しUIはまだない。
- LAS/LAZ: XYZ、強度、RGBを取り込む。RGB表示は16ビット色を前提とする。GPS時刻、Extra Bytes、分類、リターン情報など、現在保持しない属性はスキャンの「取り込み時に省略した属性」に表示する。
- 原解像度チャンクは最大65,536点・最大32 MiB。全点をRAMに展開せず、インデックス構築・範囲判定・書き出しをチャンク単位で行う。
- 原解像度はチャンクごと、LODはノードごとにbyte shuffle + Zstd level 1で可逆圧縮する。圧縮して増えるブロックは無圧縮で保存する。元の属性のbit列、点ID、除外マスクとの対応は変わらない。
- 取り込み時のE57点属性変換、leafのLOD生成・点／LOD圧縮を並列処理する。ワーカー数はCPU数−1（最小1・最大8）、処理中と書き込み待ちの変換バッファーは既定256 MiBの予約枠で制限する。アプリ全体のRAM上限ではない。空間分割、読み出し、書き込み、親LOD構築は直列。詳細は[内部形式の並列取り込み](docs/internal-format.md#並列取り込み)を参照。
- 点のRGBはsRGBとして表示する。経路は[Potreeメモ](docs/potree-rendering-notes.md#rgbの表示経路)を参照。alphaは色変換しない。
- 描画上限の既定は200万点で、画面から調整できる。移動中は上限の1/8（32,000〜300,000点）で更新し、150ms静止したら詳細化する。展開済みノードのキャッシュは既定256 MiB。キャッシュはスキャンのローカル座標で持つため、カメラ移動や位置合わせの適用ではディスクから読み直さない（有効な除外レイヤーが変わると破棄する）。GPUではスキャンごとの変換を描画時に掛けるため、変換の入力・適用・元に戻すは次の読み込みを待たずに表示へ反映する。
- ノード／チャンクのメタデータはRAMに保持する。GPUへのノード単位の常駐管理、RAM/VRAMに応じた自動調整は今後の実装。

既存の無圧縮プロジェクトも引き続き開ける。「ツール → 旧形式のデータを圧縮」（旧形式のデータがあるときだけ有効）で、履歴や除外を保持したまま旧形式の点とLODを圧縮できる。新データを全ブロック読み戻して照合してから確定し、旧資産を削除する。変換中は新旧データを同時に置くディスク容量が必要。

## 未実装・制約

ICP、SOR（統計的外れ値除去）、複数スキャンをまとめた間引き、統合点群、3Dボックス切り出し、LAS/LAZの分類・GPS時刻などの書き出し、画像再着色、平行投影、処理の途中再開は未実装。履歴はリビジョン単位の削除と未使用データのクリーンアップまで実装し、複数リビジョンの集約は未実装。

編集のたびにプロジェクトのメタデータ（`project.json`）全体を書き直す。Trimbleの848万点で約0.5 MBで、点数に比例して増える。億点規模ではメタデータの分割が必要になる。

取り込み後の除外は原解像度点にも反映するが、除外後のLOD再生成は未実装。遠景では代表点が減り、表示密度が下がる場合がある。プレビューは書き出し結果そのものではない。

現在の座標単位はメートルを前提とする。単位変換・座標参照系の変換は行わない。異なる座標メタデータのスキャンを一つのE57に書き出す場合はエラーにする。

E57の保存対象は利用ライブラリが解釈できる点属性・標準メタデータ・画像。元XMLを監査用に保存するが、独自のXML構造を含むファイル全体の完全な再現は保証しない。元の点順序は空間分割で変わる。同じGUIDを持つ入力の重複取り込みについては、書き出し時のGUID再割り当てが今後必要。

同一プロジェクトを複数プロセスから同時編集するための排他制御は未実装。キャンセルや失敗で残る`staging/`・未参照データは「履歴のクリーンアップ」で削除する（自動では消さない）。元ファイルを含むディスク容量と、一時的な作業容量が必要。

## CLIと検証

```powershell
cargo run -p geemil-core --release -- import work-data/trimble Trimble_StSulpice-Cloud-50mm.e57
cargo run -p geemil-core --release -- inspect work-data/trimble
cargo run -p geemil-core --release -- compress work-data/trimble
cargo run -p geemil-core --release -- subsample work-data/trimble-copy 0.05
cargo run -p geemil-core --release -- noise work-data/trimble-copy 0.1 4
cargo run -p geemil-core --release -- export work-data/trimble work-data/trimble-roundtrip.e57
cargo run -p geemil-core --release -- export-las work-data/trimble work-data/trimble.laz
cargo run -p geemil-core --release --example verify_e57 -- Trimble_StSulpice-Cloud-50mm.e57 work-data/trimble-roundtrip.e57
```

`verify_e57`は未編集の書き戻しを検証するためのツール。点順序によらない数値属性のハッシュ集計、点数、schema、scan pose、image pose、画像対応、投影パラメーター、画像・マスクのハッシュを照合する。全点をメモリに格納しない。ハッシュ照合は暗号学的な完全一致証明ではない。

小さな検証用E57を生成するコマンドもある。

```powershell
cargo run -p geemil-core -- demo work-data/demo.e57
```

```powershell
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
```

27件の結合テストと10件の単体テストで、複数スキャンと複数画像の保持、pose、元ファイルなしの再開、原解像度での奥行き選択、範囲内・範囲外・奥行き無制限の除外と表示プレビューの一致、未保存の作業状態と保存・分岐・切り替え、元に戻すためのスナップショット、フォルダーの変換の合成と移動時の補正、リビジョンの削除、未使用データのクリーンアップ、処理途中のキャンセル、LAS/LAZ取り込み、ノイズ除去とボクセル間引きの総当たり結果との一致とチャンク分割への非依存、LAS/LAZ書き出しでの強度・色・変換・除外・座標系の保持とスキャン別出力、少ない描画枠での複数スキャン表示、球面座標・scaled integer・無効点・大きな整数属性を検証する。加えて、旧形式からの圧縮変換、変換中断、キャッシュ再利用、リビジョンによる無効化、浮動小数点のbit保持、圧縮データの破損検出、ワーカー処理の重なりと出力順序、完了結果のメモリ予約、ワーカーエラー、1／4ワーカーでの出力一致、インデックス構築中の中断、同一点の大量重複を検証する。

ローカル実データでも取り込みと未編集E57の書き戻しを照合した。

| データ | スキャン | 点数 | 画像 | 確認 |
| --- | ---: | ---: | ---: | --- |
| manitouNoInvalidPoints.e57 | 5 | 1,095,702 | 5 | 元の点属性、スキャン・画像pose、投影・画像データ |
| Trimble_StSulpice-Cloud-50mm.e57 | 5 | 8,484,455 | 0 | RGBを含む元の点属性、スキャンpose、DirectX 12表示 |

この規模での確認は、億点以上の性能検証を置き換えるものではない。次の段階で大規模データの処理時間・RAM・一時ディスク使用量を計測する。

Zstd導入後の実データの資産容量（点・LOD・画像・元XML、manifestを除く）は、manitouが104.1 MB→34.4 MB、Trimbleが684.5 MB→220.4 MB。既存プロジェクトのコピーを変換して検証した。

取り込みの並列化後、Trimbleの848万点を同じPCのRelease版で計測した。変更前は約12.6秒、変更後は1ワーカーで約9.5秒、8ワーカーで約7.2〜7.6秒。並列化に加えてLOD候補の全点ソートを省いた改善を含む。ローカルディスク／OSキャッシュの影響がある実測値で、ストレージや点属性によって変わる。変更前のプロジェクトと全原解像度チャンク・点参照・木構造・全LODを照合した。画像入りmanitouでも同じ照合を行った。

点群処理と書き出しも同じTrimble（848万点）のRelease版で計測した。5cmのボクセル間引きが約1.0秒、続けて半径0.1m・4点未満のノイズ除去が約1.6秒（どちらもスキャンごと・最大16スレッド）。全点のLAS書き出しが約2.7秒（221 MB）、LAZが約4.6秒（104 MB）。

工程表示ごとの経過時間と取り込み全体を測るには、未作成の出力フォルダーを指定する。第3引数はワーカー数（0は自動）、第4引数は変換バッファーの予算MiB、第5引数は任意の比較用プロジェクト。工程の処理は重なるため、表示された時間は各工程の単独CPU時間ではない。

```powershell
cargo run -p geemil-core --release --example import_bench -- Trimble_StSulpice-Cloud-50mm.e57 work-data/bench-8 8 256
```

CPU側の読み込みは、`view_bench`で同じ周辺を少しずつ回転して計測できる。GPU転送・描画は含まない。Trimbleの約20万点では、導入前のDebug版が毎回約122〜131ms、キャッシュ導入後のDebug版は再利用時約7〜9ms。圧縮後のRelease版は初回約21ms、再利用時約1.5〜1.8msだった。ディスク読み込み・展開・座標変換の初回コストは残る。DebugとReleaseの数字を同じ条件の高速化率として比較しない。

```powershell
cargo run -p geemil-core --release --example view_bench -- work-data/trimble
```

選択範囲の除外は`selection_bench`で計測できる。初期の全体表示で画面中央の正方形（第2引数は半幅、0.5で画面全体）を奥行き（第3引数、m）付きで除外する。プロジェクトに除外レイヤーを確定するため、コピーに対して実行する。原解像度チャンクのうち選択範囲・奥行きに入り得ないものは読み込まない。Trimbleの848万点のRelease版で、変更前は範囲によらず約2.4秒、変更後は中央の小範囲で約0.5秒、画面全体・奥行き0.5mで約0.75秒、全点除外で約1.2秒。除外マスクは変更前とbit単位で一致した。

```powershell
cargo run -p geemil-core --release --example selection_bench -- work-data/trimble-copy 0.05 0.5
```

第3引数を`inf`にすると奥行きを制限しない。第4引数に`outside`を指定すると範囲外の除外（切り出し）を計測する。同じ848万点で中央の正方形（半幅0.15）の外側26.7万点の除外は約0.8秒、内側821.7万点の奥行き無制限の除外は約0.85秒で、両者の合計は全点数と一致した。

開発用のGPU起動テストでは、2秒間カメラを回転・平行移動し、移動中にもノードの更新が完了することを確認して画面を保存する。

```powershell
cargo run -p geemil-desktop --release -- work-data/trimble --smoke-test work-data/preview.png --smoke-orbit
```

```powershell
cargo run -p geemil-desktop --release -- --smoke-test work-data/colors.png --smoke-colors
```

除外プレビューの確認では、起動1秒後に画面中央を矩形選択し、赤表示の点数と基準点を出力して画面を保存する。`inside`は奥行き0.5mの範囲内、`inside-all`は奥行き無制限の範囲内、`outside`は範囲外の除外。

```powershell
cargo run -p geemil-desktop --release -- work-data/trimble --smoke-test work-data/select.png --smoke-select outside
```

画面の確認用に、ダイアログを開いた状態（`revisions`・`shortcuts`・`new-project`・`cleanup`・`save-as`）を保存できる。プロジェクトを指定しないと起動画面を保存する。

```powershell
cargo run -p geemil-desktop --release -- work-data/manitou --smoke-test work-data/revisions.png --smoke-dialog revisions
```

`--smoke-script`は、表示の読み込み後に操作を順に実行し、各操作後のスキャン数・フォルダー数・レイヤー数・リビジョン数・未保存の有無・元に戻す／やり直すの可否を出力する。操作は`exclude`・`undo`・`redo`・`save`・`folder`・`remove`・`measure`・`preview`（最初のスキャンの変換を入力するが適用しない。動いた表示点数を出力する）・`apply-transform`（入力中の変換を適用する）・`subsample`（5cmのボクセル間引き）・`noise`（半径0.1m・4点未満のノイズ除去）。`--smoke-dialog`には`subsample`と`noise`も指定できる。プロジェクトを書き換えるため、コピーに対して実行する。

```powershell
cargo run -p geemil-desktop --release -- work-data/manitou-copy --smoke-test work-data/flow.png --smoke-select inside-all --smoke-script exclude,undo,redo,folder,save,remove,measure
```
